PAW：函数即权重，0.6B打平32B

今天给大家带来一篇将模糊函数编译为神经权重的论文PAW，让0.6B小模型在模糊任务上媲美32B大模型，推理内存仅1/50。

🔑 关键方法：
1️⃣ 神经编译器+冻结解释器：用4B Qwen3模型作为编译器，将自然语言规范转化为离散伪程序（文本）和连续LoRA适配器；0.6B解释器固定不变，只负责加载LoRA并执行。
2️⃣ 双阶段编译：第一阶段伪编译器（未训练，仅靠提示模板）生成干净的任务重述+示例；第二阶段LoRA编译器（已训练）从隐藏状态中提取特征，通过共享基座线性组合生成LoRA权重，注入解释器各层。
3️⃣ 混合程序形式：离散部分（伪程序）屏蔽输入噪声，连续部分（LoRA）提供细粒度行为控制，两者联合指导解释器生成输出。

💡 核心创新：
1️⃣ 重新定义编程范式：从“每输入调用大模型”变为“每函数编译一次，本地运行”——大模型只在编译时用一次，执行时完全离线，像调用Python函数一样调用神经权重。
2️⃣ 编译器-解释器彻底解耦：编译器可以换（比如换成VL模型处理图像），解释器不变；LoRA热插拔，同一个解释器可服务无数个PAW程序。
3️⃣ 首次提出“模糊函数编程”概念并配套10M样本数据集FuzzyBench，覆盖800+子类任务（分类、解析、工具调用等），为训练此类系统提供基准。

📊 实验效果：
✅ 在FuzzyBench上，0.6B PAW以73.78%准确率超越32B直接提示的68.70%，推理内存仅1.2GB（32B需60GB），缩至1/50。
✅ 量化后Q5_K_M基座+Q4_0 LoRA共约646MB，在MacBook M3上跑30 tok/s，单程序仅23MB，冷启动0.48秒。
✅ 多模态扩展：仅换编译器为VL模型，PAW在CoSyn图表任务上（电路、化学、音乐）全面超越4B VLM基线，解释器仍为0.6B。
