大模型Agent新范式：状态先于像素

今天给大家带来一篇颠覆性论文：StateAct，它让电脑操控Agent直接从程序状态（文件、后端、DOM）下手，而非依赖截图，在超长任务中性能飙升，成本却直降9倍。

🔑关键方法
1️⃣ 主智能体通过代码（bash、Python、文件编辑器）直接读写程序状态，告别“看截图猜状态”的模糊性，只有在极少数无法用代码触及的场景（如拖拽画布、非脚本化弹窗）才调用GUI子智能体。
2️⃣ 独立“完成门”验证：一个不读主Agent历史、只看最终持久化产物的裁判，单独检查结果是否完整、路径是否正确，避免Agent自我叙述导致的误判。
3️⃣ 上下文管理：通过“新鲜上下文”委托子任务、自动压缩历史、外部化计划清单，让主Agent在数百步的长程任务中保持专注，不被陈旧的截图信息淹没。

💡核心创新
1️⃣ 状态接地（State-Grounding）：把Agent的感知-动作闭环从像素通道切换到状态通道。渲染是损性、非单射的（不同状态可能显示相同像素），而代码直接读取值、公式、后台数据，是精确可逆的。这从根本上消除了长程任务中逐像素误差累积的隐患。
2️⃣ 分层设计：主Agent只通过代码操作状态，GUI子Agent仅在需要纯视觉交互时才被动态调用（仅28/108任务用到，占主Agent步骤的1.1%）。这种“代码优先，视觉兜底”的分工，让主干从感知瓶颈中解放出来。
3️⃣ 验证即状态：检查任务是否成功不依赖Agent的自述，而是直接检验持久化产物（如文件内容、应用后端记录）。验证门独立于Agent轨迹，避免了自我反思中的一致性偏差。

📊实验效果
✅ 在OSWorld 2.0上，使用Claude Opus 4.8，StateAct将二值成功率从20.6%提升至26.9%，部分成功从54.8%提升至61.6%，同时每个任务成本从约72美元降至约7.8美元，降低约9倍。
✅ 即使只用紧凑型GUI子模型（SFR-CUA，31B），在四个较短基准上性能几乎不变，说明长程任务瓶颈确实已从感知转向推理，而代码操作状态才是增益主因。
✅ 错误分析显示，79个非完美任务中38个是推理错误（如理解偏差、值写错），14个是验证门没捕捉到的结构问题；仅有约20%触及视觉或指令模糊瓶颈。状态接地成功将“看不见”的感知错误转化为“想不对”的推理错误。
