MIRIX-2.0: Multi-Agent Memory System

📅 2026-11-18

MIRIX AI等推出Agent记忆系统：LoCoMo达91.4%！

一、引言

一个长期使用的个人助手，需要记住用户几个月前提过的偏好；一个购物 Agent，则需要从失败经历中学会检查商品规格。两者都需要长期记忆，却对记忆提出了不同要求：前者要保留具体细节，后者要提炼可复用的行动方法。

现有方案往往面临取舍：压缩历史可能丢失日期和数量，完整保存又会让检索越来越困难；用模型参数记忆则需要训练，也不方便接入闭源模型。

MIRIX-2.0 将记忆保存、关系索引和后台整理拆成不同层次：用多智能体写入分类记录，用可追溯超图连接证据，再通过 AutoDream 整理实体和任务技能。理解这套设计的关键，是区分记录本身与找到记录的索引。

二、核心方法

Typed Evidence Plane：分类保存记忆记录

系统由 Meta Memory Manager 判断一条输入应更新哪些记忆，再交给对应的写入智能体。六类记忆分别是核心记忆、情景记忆、语义记忆、程序性记忆、资源记忆和 Knowledge Vault。

其中，情景记忆记录发生过的经历，语义记忆保存相对稳定的事实；程序性记忆则保存可供 Agent 复用的技能。只有情景和语义记录进入后续超图索引。

每条情景或语义记录都有不可变的行 ID，并携带文本、事件时间、提及或写入时间、来源信息和检索向量。具体记录保存在向量数据库中，图里主要保存结构及指向记录的引用。

写入顺序很重要：先提交记录，再构建图索引。即使图写入失败，也不会回滚已经保存的记忆；图读取报错时，系统还能回退到直接检索证据。这保护的是已写入记录，而不意味着写入阶段一定捕获了输入中的所有细节。

Provenance Hypergraph：用多元事实连接可追溯证据

普通关系图通常把事实拆成一组二元关系，但一次旅行可能同时涉及旅客、出发地、目的地、同行者和时间。拆散后，哪些信息属于同一次旅行就可能变得难以判断。

MIRIX-2.0 用多元事实帧保留这些参与者及其角色：

$$f=\left(p,\,\{(r_j,a_j)\}_{j=1}^{d_f},\,\ell_f,\,\tau_e,\,\tau_m,\,C_f\right)$$

这里的 $p$ 是关系，$r_j$ 和 $a_j$ 表示参与者角色与实体，$\ell_f$ 保存日期、价格等具体值，$C_f$ 指向支持该事实的来源记录。

写入图时，系统先抽取实体和事实，再用近邻搜索提出可能重复的实体，由语言模型谨慎判断是否为同一对象；向量相似度本身不能直接决定合并。针对高信号细节的遗漏，系统还可以进行一次受限的补充抽取。

情景事件与稳定事实采用不同的身份规则：重复出现的语义事实可以累积来源引用；情景事实则加入事件时间，没有明确事件时间时使用不可变记录 ID，避免仅因措辞相似就合并不同经历。

查询时，检索器先按问题类型制定预算，再从匹配问题的实体锚点进入图：

  • 基础召回通道查找锚点关联的记录，并沿事实帧找到相关来源。
  • 关系引用通道筛选与问题关系匹配的事实帧，取回其明确引用的记录。
  • 两路结果经过排序和去重后，将图事实与来源记录一起交给回答模型。

例如，单值查询的预算为最多 6 条基础记录和 4 条关系引用记录；计数问题需要更宽的证据范围，预算分别为 8 条和 12 条。回答草稿若出现明确不确定、缺失所需数值或与证据不一致等情况，还可触发额外检索和改写。预算限制的是单次检索查看的证据规模，并不等同于已经证明历史增长时的实际延迟恒定。

AutoDream：后台整理实体与任务技能

AutoDream 不在关键写入路径上运行，而且对语义记忆和程序性记忆采取不同策略。

对语义记忆，它只从新增语义记录涉及的实体出发，在同类型近邻中寻找可能重复的对象。语言模型确认后，系统合并锚点的引用并调整关联边，但不改写向量数据库中的记忆，也不合并事件事实节点。合并候选有数量上限，被否定的候选对会缓存，避免反复判断。

对程序性记忆，AutoDream 则从已完成的任务会话中提炼“值得复用的经验”和“需要避免的错误”，再由整理器创建、修改或删除技能。技能编辑可以引用经验，引用中的原文需经过核验。这个分支会改变提供给 Agent 的行动指导，因此不能与语义分支的“保留记录、只整理索引”混为一谈。

三、实验

在用户记忆实验中，研究者比较了三种配置：M0 为无图、无 AutoDream 的平面向量记忆；M1 加入超图但关闭 AutoDream；M2 则同时启用超图和 AutoDream。

在对话记忆基准 LoCoMo 上，M0、M1、M2 的准确率依次为 85.7%、88.4% 和 91.4%；在 LongMemEval-S 上依次为 58.8%、70.0% 和 72.6%。两项测试均采用语言模型裁判评分。M2 在 LongMemEval-S 上比最强对比方法 HyperMem 高 14.3 个百分点；但在 LoCoMo 的开放域和单跳问题上，HyperMem 仍有更高分数。

长文档问答使用关闭 AutoDream 的 M1：单跳任务达到 83.0%，多跳任务达到 71.0%，分别比 HyperMem 高 31.0 和 22.0 个百分点。不过，在需要推理的 DetectiveQA 上，M1 的 64.8% 低于 HyperMem 的 66.2%。这些结果比较的是完整流程，不能单独证明某个组件带来了全部收益。

程序性记忆实验先用训练任务提炼技能，再冻结记忆，测试其在新任务上的复用能力。在 ALFWorld 中，使用 GPT-6 Luna 时，MIRIX-2.0 的平均成功率为 76.4%，无记忆为 69.4%，对比方法 AWM 为 73.6%；但 MIRIX-2.0 在三次运行中的标准差为 6.2 个百分点，优势的稳定性仍需更多验证。

在 WebShop 中，MIRIX-2.0 的平均成功率为 37.4%，高于无记忆的 31.9% 和 AWM 的 36.0%。在跨 30 天任务的 MetaClaw-Bench Part I 上，使用 GPT-5.2 时，其得分为 49.2%，MetaClaw 技能库的报告值为 44.0%；这一比较并非完全受控的重新运行。

效率实验均关闭 AutoDream。M1 在五项计时基准上的回答速度快于 HyperMem，但文档图构建使录入时间达到平面记忆的 3.8 至 4.0 倍；完整 M2 系统的总耗时未测量。在 WebShop 上，MIRIX-2.0 每次运行的训练和测试 token 分别为 1.815M 和 4.975M，均为对比记忆方法中最低；但在 ALFWorld 上，其测试 token 为 3.813M，反而是这些记忆方法中最高的。
