Tools Need Not Speak in Text: Latent Context Compression for Agents

📅 2026-11-08

清华推出Agent潜表示压缩：网页问答Token消耗最高降89.24%！

一、引言

一个使用搜索工具的Agent，往往需要反复经历“搜索、阅读结果、继续搜索”的过程。问题在于，搜索结果虽然能提供证据，也会带来大量与当前任务无关的网页摘要和细节。每轮都把原始结果追加进上下文，模型需要处理的内容便会迅速膨胀。

例如，在一个搜索轨迹示例中，到第4步时，工具返回内容已占上下文Token的96.7%。这不仅增加计算开销，也可能让关键证据淹没在噪声中。传统做法是删减Token或生成文本摘要，但压缩结果仍然需要组织成可读的离散文本。

清华大学团队提出的Coca-Cola换了一种思路：工具结果不一定要以文本形式交给Agent，也可以先压缩成连续向量，再直接送入模型。在网页搜索问答实验中，这一方法既降低了Token消耗和运行时间，也改善了最终答案指标。

二、核心方法

Context-Aware Encoder与Latent Adapter：生成可供Agent使用的潜表示

Coca-Cola的压缩对象是每次工具调用返回的工具观测，例如一组搜索结果。它不要求压缩结果成为一句人类可读的摘要，而是将结果编码成少量潜在Token：处在连续空间中的高维向量。

但一段搜索结果里哪些信息值得保留，取决于Agent正在解决什么问题、当前推理到了哪一步。因此，上下文感知编码器会同时读取任务指令、当前步骤的推理状态和工具观测。例如，Agent正在查找某位赛车手的出生年份时，搜索结果中的姓名可能是下一次搜索的关键，而比赛过程的详细描述未必有用。

编码器使用小型语言模型产生隐藏状态；随后，潜表示适配器将其转换为固定数量的向量，并映射到目标Agent的输入嵌入空间：

$$z_t=A_{\phi}\!\left(C_{\theta}(q,r_t,o_t)\right)$$

这个公式表示，任务指令 $q$、当前推理状态 $r_t$ 和工具观测 $o_t$ 依次经过编码器与适配器，得到潜在Token $z_t$。

这些向量会插入Agent的输入嵌入序列，并由特殊边界标记包围。Agent接收到的因此不是一段先解码成文字的摘要，而是一组可直接参与后续计算的连续表示。

潜在Token的理论优势在于：一个文本位置只能从固定词表中选择一个符号，而一个向量位置可以通过多个数值维度联合编码信息。不过，这只是特定有限精度假设下的容量分析；向量实际能保留多少信息，还取决于压缩器的编码能力和Agent的使用能力。

Action-Preserving Training：让压缩结果保留决策信息

能把长文本压成向量，并不意味着向量恰好包含Agent需要的内容。Coca-Cola没有要求压缩器尽量还原工具原文，而是以下一步动作为训练目标。

训练时，同一个冻结的目标Agent分别接收两种输入：一种包含完整工具观测，另一种用潜在Token替代当前观测。前者产生的动作分布作为教师信号，后者产生学生分布。训练同时使用分布对齐和轨迹监督：

$$\mathcal{L}=\lambda_{\mathrm{KL}}D_{\mathrm{KL}}(p_{\mathrm{full}}\parallel p_{\mathrm{latent}})+\lambda_{\mathrm{CE}}\mathrm{CE}(y_{t+1},p_{\mathrm{latent}})$$

这个损失让压缩观测下的动作预测接近完整观测下的预测，同时利用轨迹中记录的下一动作Token提供监督。

其中，KL散度用于约束两种输入下的预测分布，交叉熵则利用记录动作提供额外监督。目标不是保证压缩后逐字复现搜索结果，而是减少压缩对后续搜索、推理或回答决策的影响。

由于潜在Token可微，梯度能够穿过冻结的Agent传回压缩模块。训练过程中，目标Agent参数保持不变，只更新编码器的LoRA参数和适配器参数。这样，压缩器学习的是目标Agent能够利用的表示，而不是独立于Agent的通用文本摘要。

Inference：在每次工具调用后替换原始观测

部署时，每当工具返回结果，压缩器就结合当前任务和推理状态生成潜在Token，再用这些向量替换原始观测，交给Agent决定下一步操作。

如果Agent继续调用工具，同样的过程会重复执行。与原始结果逐轮累积相比，历史工具观测以更紧凑的形式留在上下文中。需要注意的是，压缩器本身仍要读取原始工具输出，因此Agent上下文缩短，并不等于工具结果完全不产生处理开销。

三、实验

实验采用网页搜索Agent，在NQ、TriviaQA、2Wiki和HotpotQA四个问答数据集上评估；前两个主要涉及事实检索，后两个需要多跳证据推理。模型配置包括Qwen3.5-35B-A3B与Qwen3.5-4B组合，以及GLM-4.7-Flash与GLM-Z1-9B组合。

比较对象包括直接追加原始结果的Vanilla Model、Token删减方法LongLLMLingua、文本摘要方法LLMSummary，以及基于原文重建训练的潜表示方法ICAE。其中，ICAE使用与Coca-Cola相同的压缩架构，有助于比较训练目标的影响。

效率方面，相对于不压缩的Vanilla Model，Coca-Cola在八组“模型配置—数据集”实验中，将输入和输出Token合计消耗降低了70.01%—89.24%，端到端运行时间降低了24.45%—55.97%。例如，在GLM模型组合的2Wiki实验中，平均输入Token从31,693.47降至3,003.38，运行时间从106.37秒降至46.83秒。

这里的压缩率按实验报告的输入、输出Token合计计算；运行时间则反映实验配置下的端到端结果，不能直接替代其他部署环境的成本测量。

任务表现方面，研究使用精确匹配率（EM，最终答案与标准答案完全一致的比例）和Token级F1衡量答案质量。Coca-Cola在全部八组配置中均高于Vanilla的EM和F1，并在其中六组同时取得所有对比方法中最高的EM和F1。

例如，在GLM模型组合的2Wiki实验中，F1从Vanilla的31.29%升至36.20%，同时总Token压缩率达到89.24%。但它并非每项指标都领先：在Qwen模型组合的TriviaQA实验中，ICAE的F1为69.27%，高于Coca-Cola的67.07%；对应压缩率分别为66.92%和83.68%。这体现了效果与压缩程度之间需要结合场景权衡。性能改善可能与过滤无关信息有关，但实验结果本身不能单独证明这一因果机制。

消融实验进一步检验了压缩预算与上下文条件。在GLM模型组合的NQ实验中，潜在Token数量从8增加到128时，F1从26.34%升至31.45%，但128个Token对应的压缩率降至73.73%。在128个Token的设置下，完整输入的EM为23.50%；去掉推理状态后降至21.45%，去掉任务目标后降至20.02%，两者都去掉后为18.34%。这些结果表明，在该实验条件下，任务目标和当前推理状态都有助于压缩器筛选决策相关信息。
