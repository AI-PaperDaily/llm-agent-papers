Clover-35B-A3B-Preview Technical Report

📅 2026-11-25

DiffuSpace 的 Clover：循环记忆结合块内双向注意力，SWE-bench Verified 达 73.6

一、引言

Agent 完成软件任务时，需要反复阅读上下文、生成工具调用，并根据执行结果继续行动。模型不仅要理解长上下文，也要在多轮交互中控制生成延迟。

自回归模型通常逐 token 生成；扩散语言模型则可以在一个文本块内并行预测多个位置，再通过去噪逐步确定结果。但并行预测要真正变快，还取决于历史上下文如何被读取、草稿有多少能通过验证，以及每轮计算本身的成本。

DiffuSpace 的 Clover-35B-A3B-Preview 将 Qwen3.6-35B-A3B 的文本骨干改造成块扩散模型：用循环状态保存已完成上下文，让当前块内的 token 双向交互，再由同一个模型验证并提交草稿。报告重点检验这套设计在 Agent 任务和推理效率上的整体表现。

二、核心方法

Clover 总参数约 35B、每个 token 激活约 3B。生成时，模型先处理提示词，再逐块产生回答：当前块并行预测，已完成的内容则作为后续块的上下文。它是 Agent 工作流中的语言模型，而不是新增了一套工具执行框架；实际工具调用和环境反馈仍由外部运行框架组织。

图1中，每组包含三个改造后的循环层和一个全注意力层，共重复十次；每层后面接专家模块。循环层负责让压缩历史与当前块交互，全注意力层保留完整注意力计算，专家模块则处理各位置的特征。

用循环记忆读取历史，让当前块双向交互

原始 Gated DeltaNet 逐位置更新固定形状的状态。Clover 保留这条干净上下文路径：对已完成 token，先衰减旧状态，再根据当前键值修正记忆：

$$ \widetilde S_i=\alpha_iS_{i-1},\qquad S_i=\widetilde S_i+\beta_i(v_i-\widetilde S_i\widehat k_i)\widehat k_i^\top $$

其中 $\alpha_i$ 控制保留多少旧记忆，$\beta_i$ 控制写入强度；更新项写入的是当前值与记忆检索结果之间的差异。

当前块去噪时，边界处的历史状态 $S_b$ 保持不变。每个位置用自己的查询向量读出历史，同时关注当前块内所有有效位置。Clover 将这两类信息放进同一个 softmax，让它们竞争权重：

$$ r_j=\frac{S_b\widehat q_j}{\sqrt{d_k}},\quad \ell_{ji}=s_h\widehat q_j^\top\widehat k_i,\quad \ell_{j,\mathrm{hist}}=b_h+c_h\log\frac{N_b}{32} $$ $$ (\{p_{ji}\},p_{j,\mathrm{hist}}) =\operatorname{softmax}(\{\ell_{ji}\},\ell_{j,\mathrm{hist}}),\quad o_j=p_{j,\mathrm{hist}}r_j+\sum_i p_{ji}v_i $$

这里 $N_b$ 是块内有效位置数，$r_j$ 是历史读出，$v_i$ 是块内位置的值；输出按同一组归一化权重混合历史与局部信息。

历史只占一个 softmax 条目，块越大，局部条目越多。因此，历史得分中的可学习项 $c_h\log(N_b/32)$ 用来校准不同块大小下的竞争关系。

图2还展示了局部双向信息的另一条通路：模型保留预训练的因果短卷积，增加仅看当前块右侧的卷积分支。右侧权重从零初始化，因而初始时不改变原有因果卷积；干净上下文处理仍只使用因果分支。块内双向可见不意味着可以看到尚未生成的未来块。

块内专家协作与双流训练

并行预测可能让块内不同 token 请求大量不同专家。Clover 的 dMoE 先为每个 token 找出得分最高的八个专家，再汇总整个块的得分，选出覆盖累计得分质量 90% 的专家池；各 token 随后只在池内重新选择专家。共享专家始终参与计算。这样既保留位置各自的选择，也鼓励块内复用专家。

模型需要同时学会去噪和因果预测。训练时，同一样本构造一份带掩码的副本和一份干净副本：带噪位置只能读取本块之前的干净上下文，以及当前带噪块，不能看到自己的干净答案。每个微批次从 $\{4,8,16,32\}$ 中采样块大小，并在注意力、循环层和专家路由中使用一致边界。

训练目标组合了两个方向：

$$ \mathcal L=\lambda_{\mathrm{BD}}\mathcal L_{\mathrm{BD}} +\lambda_{\mathrm{AR}}\mathcal L_{\mathrm{AR}} $$

其中 $\mathcal L_{\mathrm{BD}}$ 在被掩码的位置预测原 token，$\mathcal L_{\mathrm{AR}}$ 在干净流上预测下一个 token；两项共同更新模型参数。

因果目标使同一骨干也能执行后续的草稿验证。报告说明了训练目标和实现，但没有给出足以重建完整训练阶段、数据来源及配比的细节。

用同一模型起草和验证

推理时，Clover 可先在一个掩码块上并行产生草稿，再用模型的因果路径逐个验证；遇到第一个拒绝的位置就停止，只提交此前通过的前缀。报告中的主评测采用基于熵的验证：对于草稿 token $d$、因果预测分布 $p$ 及其熵 $H$，接受条件为

$$ p(d)\geq\delta\exp(-H),\qquad H=-\sum_{v\in\mathcal V}p(v)\log p(v) $$

该条件根据预测不确定性调整接受门槛；它比要求草稿必须等于因果贪心预测的精确验证更宽松，不保证输出与因果贪心解码完全一致。

去噪期间的预览缓存不会直接成为历史；已确定的内容经过因果干净路径，才用于推进循环状态和缓存。模型还使用重复惩罚及长度相关的停止控制，避免扩散解码中偶发的重复或过长输出。

同样的块内交互也被用于一个单独的 Clover Decision 变体：共享材料和多个问题进入模型后，固定模板中的答案位置同时被掩码，一次去噪预测最多八个答案。各答案位置可以交换中间特征，但单次预测并不保证满足所有逻辑约束。

三、实验

Agent 能力。 主表中的基线由研究者按统一评测协议复现，各模型使用官方推荐的解码配置。软件任务使用 Codex 或 Terminus 2 作为运行框架，每题运行三次取平均。Clover 在 SWE-bench Verified 得到 73.6，Qwen3.6-35B-A3B 为 65.8；在 Terminal-Bench 2.1 上分别为 51.7 和 43.1。这两项分别检验仓库级问题解决与终端环境任务，结果反映的是模型配合相应框架后的整体表现，而非单独证明某个模块带来增益。

生成速度。 在单张 H200、BF16、批量为一的测试中，Agent replay 只让模型续写历史轨迹前缀，不执行命令。Clover 的解码吞吐为 556.6 token/s，Qwen3.6 加 DFlash 2 为 396.7 token/s；但在 MATH-500 上，前者为 465.2，低于后者的 604.3 token/s。每轮提交更多 token 并不必然更快，草稿和验证的成本同样重要。

图4使用包含 prefill 和尾部排空的端到端口径，与上述解码吞吐不能直接混用。在块大小为16、启用长度和思考控制时，Clover 在 H200 上达到 515 token/s，在 GB300 上达到 680 token/s；该实验同样不衡量 Agent 任务成功率。

受限显存部署。 在 RTX 5070 Ti 16GB、CPU 与 GPU 混合执行的 MATH-500 测试中，Clover 将专家权重量化为 INT4，并依据数学任务的路由统计调整专家放置。top-8 验证的解码速度从 66.64 提高到 97.52 token/s，人工复核准确率为 97.6%；改为 top-6 后速度为 106.25 token/s，准确率降至 96.0%。这是特定硬件、任务和专家放置下的速度—质量取舍。

联合决策。 在使用同一决策模型的内部 500 组问题上，联合预测的逐题准确率从 90.37% 升至 93.88%，整组全对率从 65.4% 升至 77.0%。这些内部数据在开发期间被反复使用，并非新的盲测。

图5中，八题联合预测的平均组延迟为 164 ms，顺序独立调用为 1243 ms，最多八路并行的独立调用为 249 ms；测试使用相同硬件和检查点，联合模式只需处理一次共享上下文。
