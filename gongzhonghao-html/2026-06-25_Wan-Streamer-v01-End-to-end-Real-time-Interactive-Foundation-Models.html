Wan-Streamer v0.1: End-to-end Real-time Interactive Foundation Models

📅 2026-06-26

阿里巴巴Wan-Streamer：全双工视听交互大模型，200ms延迟终结机器人对话卡顿？

一、引言

与AI对话时是否经历过这样的尴尬：数字人说完话后画面凝固，或是语音刚吐出前半句，行为却已提前结束？这种不自然的体验源于当前多模态系统的“拼凑式”架构——它们将语音识别、大语言模型、文本转语音、视频生成等模块独立运作，模块间的等待时间不断累积，导致响应迟缓、音画不同步。

为了解决这一痛点，阿里巴巴Wan团队提出了Wan-Streamer，一个从零设计的原生流式、端到端交互基础模型。该模型将语言、音频、视频同时作为输入和输出，在一个统一的Transformer中通过块级因果注意力完成增量式流式生成。实验结果令人印象深刻：模型仅需约200毫秒即可生成响应，结合双向网络延迟后，总交互延迟大约为550毫秒，首次实现了亚秒级全双工视听交互。

二、核心方法

Wan-Streamer的核心洞察在于：实时视听交互并非简单等同于“理解+生成”的拼接，而应是一个持续进化的因果流，其中用户的感知与智能体的反馈在时序上紧密重叠。

1. 原生流式交互建模

传统的多模态系统通常将交互划分为单向的“感知-推理-反应”流程。Wan-Streamer则将交互建模为一个连续的因果序列。令 $u_k = (u_k^{\mathrm{t}}, u_k^{\mathrm{a}}, u_k^{\mathrm{v}})$ 表示第 $k$ 个流式单元中用户的文本、音频和视频观测，$y_k = (y_k^{\mathrm{t}}, y_k^{\mathrm{a}}, y_k^{\mathrm{v}})$ 表示智能体的响应。模型利用完整的因果历史进行预测：

$$p_{\theta}(y_{1:K}\mid u_{1:K})=\prod_{k=1}^{K}p_{\theta}\!\left(y_{k}^{\mathrm{t}},y_{k}^{\mathrm{a}},y_{k}^{\mathrm{v}}\mid u_{\leq k}^{\mathrm{t}},u_{\leq k}^{\mathrm{a}},u_{\leq k}^{\mathrm{v}},y_{这一公式意味着模型在生成当前响应时，可以即时利用用户最新的意图、表情或语气变化，无需等待整段语音或视频流处理完毕。

上图展示了Wan-Streamer的统一架构：语言、音频和视频在单个Transformer中作为输入和输出共同处理，由块级因果注意力驱动增量流式生成。

2. 统一全模态因果架构

为了实现原生流式响应，研究者对整个架构进行了彻底的因果性重设计。包括严格因果的音频和视频变分自编码器、因果编码器与解码器，以及块级因果注意力机制。

在训练阶段，音频和视频响应被表示在连续潜在空间中，并通过条件流匹配联合生成。对于模态 $m$（音频或视频），定义 $z_0^m$ 为干净目标潜在表示，$\epsilon^m \sim \mathcal{N}(0,I)$ 为高斯噪声。在流时间 $\tau$ 上，构建带噪潜在表示：

$$z_{\tau}^{m}=(1-\tau)z_{0}^{m}+\tau\epsilon^{m},\qquad\frac{\partial z_{\tau}^{m}}{\partial \tau}=\epsilon^{m}-z_{0}^{m}.$$

模型通过统一的扩散Transformer $f_{\theta}$ 来估计速度场，从而预测干净潜在表示。这种设计使得语音生成、面部动态、表情变化等不同模态的行为能够在同一个因果上下文中协同学习。

训练分为三个阶段：第一阶段进行独立任务预训练，将理解与生成任务对齐到同一个序列模型中；第二阶段进行端到端的交互训练，引入真实的双工交互数据；第三阶段通过蒸馏技术，将强大的教师模型压缩为学生模型，大幅降低推理延迟，同时引入滚动蒸馏以缓解长序列生成中的退化问题。

3. 低延迟推理系统

尽管Wan-Streamer是一个统一的端到端模型，但在部署时采用了一种精巧的“思考者-执行者”流水线来最大化硬件利用率。

如上图所示，系统将思考者与执行者并行运作：
- 思考者：负责接收用户观测、更新键值缓存、执行语言预测并进行解码。
- 执行者：仅负责运行流匹配求解器，生成下一帧的音频-视频潜在表示。

这一调度使得当前帧的感知推理、上一帧的视听解码以及下一帧的潜在去噪能够完全重叠。在该设计下，每帧吞吐量主要受限于执行者的耗时，系统可以以160毫秒为流式单元持续运行，实现200毫秒模型侧响应延迟和550毫秒总交互延迟（含350毫秒双向网络延迟）。

三、实验与性能

Wan-Streamer的实验评估涵盖延迟对比与交互自然度分析两个方面。

1. 响应延迟对比

下表展示了Wan-Streamer与多种主流实时对话系统的延迟对比。Wan-Streamer是唯一同时支持文本/音频/视频输入和输出的模型，且能够生成同步的音频和视觉响应。

系统 交互范围 用户可见响应延迟 备注
Doubao Realtime Voice 语音到语音 ~1秒 仅语音，无视觉输出
GPT-4o / Realtime API 语音到语音、音/视输入 协议依赖 未支持同步视觉生成
Moshi 语音到语音 160-200毫秒 纯语音，全双工
Qwen3.5-Omni 音/视输入，语音/文本输出 第一包延迟547毫秒 仅输出语音或文本

从上表可以清晰看到，虽然一些语音系统如Moshi汇报了较低的模型延迟，但它们不支持同步的视觉响应。而整合了视觉响应的系统中，Wan-Streamer在延迟与功能完整性之间取得了最佳平衡。

2. 交互自然度与全双工能力

除了响应速度，Wan-Streamer在交互自然度方面也有突出表现。在空闲状态，智能体能保持身份特征、视线、姿态、呼吸与微妙的面部动作，而非凝固为静态画面。在倾听状态下，模型可以产生与用户话语节奏相匹配的非语言反馈，如视线移动、点头、微表情和姿势变化。

重要的是，中断与主动发言能力作为模型端的原生行为得以学习。由于训练数据将用户输入与智能体输出放置在共同的因果时间线上，模型自然学会了何时继续、何时暂停、何时抢夺话轮。当用户中断时，模型可以实时调整、缩短或改变自身的发言内容。同样，当视觉流中出现事件时，模型可以主动发起评论或提问，而非被动等待用户指令。

四、展望

Wan-Streamer的提出标志着多模态交互迈向了一个新阶段——它不再需要工程师手动拼接语音识别对话管理视频生成等组件，而是将整个交互过程作为一个统一的因果系统进行学习。当前v0.1版本以192p分辨率运行，随着算力提升，向更高分辨率的扩展是直截了当的路径。未来，对于数字人助理、虚拟偶像直播、远程教育、具身智能体等场景，这种原生全双工端到端架构或将成为标准范式。

下一个值得思考的问题是：当AI能同时在语速、语气、表情和微动作层面与人类保持实时共鸣时，人类与机器的互动边界会发生怎样的改变？
