Rubric-to-Code Credit Assignment for Reinforcement Learning

📅 2026-09-02

蚂蚁集团RCCA框架登顶ArtifactsBench：41.25分超越Claude Opus 4.5

一、当生成式代码撞上“交互”这道墙

大型语言模型正在从“写代码片段”走向“交付可用软件”。在交互式网页应用生成场景中，模型需要根据自然语言需求，产出完整的HTML、CSS和JavaScript应用，并确保按钮点击、状态更新、DOM渲染等用户可感知的行为全部正确。

但这一任务的训练信号存在一个根本性错配：标准GRPO将多个功能需求折叠成一个序列级奖励，再把优势值均匀施加到所有生成token上。模型知道“这个应用不合格”，却不知道“是哪段代码让它不合格”。蚂蚁集团Inclusion AI与中南大学联合提出的Rubric-to-Code Credit Assignment（RCCA）框架，正是要解开这个信号黑箱。

论文提出的Ling-RCCA-Flash在MiniAppBench上取得41.25分，从Ling-3.0-Flash的9.05分跃升32.20分，以微弱优势超越Claude Opus 4.5；在ArtifactsBench上更以76.19分登顶官方排行榜，超越GPT-5达3.64分。

二、RCCA的三层信号修复机制

1. Rubric驱动的训练数据构造

传统RL训练任务往往只有一个模糊的自然语言请求，缺乏可验证的细粒度目标。RCCA为每个训练样本显式绑定一组功能rubric $\mathcal{R}=\{r_{1},\ldots,r_{M}\}$，每条rubric描述一个可独立检查的用户侧需求。

这些rubric被分为两类：初始状态rubric要求页面加载后立即满足某些属性（如特定元素存在、默认值正确）；动态rubric要求用户在交互后触发预期行为（如点击打开面板、输入更新内容）。同一组rubric贯穿训练全程，既用于评估采样结果，也用于计算层级奖励，还用于后续的代码定位——这让任务构造、奖励计算和信用分配三条线在同一套语义框架下对齐。

2. 分层奖励：把“失败”拆成四种颜色

直接聚合rubric通过率有一个盲区：输出格式错误、JavaScript语法错误、运行时崩溃、功能部分缺失，是四种性质完全不同的失败，但标量奖励会把它们混为一谈。RCCA设计了一个四阶段门控奖励：

$$R(y,\mathcal{R})=\begin{cases}0,&F(y)=0,\\0,&S(y)=0,\\0.1,&E(y)=0,\\R_{\mathrm{rubric}},&\text{otherwise},\end{cases}$$

其中 $F$、$S$、$E$ 分别表示格式校验、源码校验和运行时校验是否通过。只有全部通过门控的应用才进入rubric级评估。这一设计让组内优势比较有了更清晰的层级结构：一个能运行但功能缺失的应用，与一个连页面都渲染不出来的应用，在奖励空间中不再混为一谈。

通过门控后，rubric级奖励按违规的重要性等级（核心功能、行为正确性、渲染质量）和违规严重程度计算：

$$R_{\mathrm{rubric}}=\max\left(0.2,\,1-\sum_{r_{j}\in\mathcal{V}}p(\ell_{j},q_{j})\right)$$

对于核心功能的严重违规，还设置了分数上限，防止被其他次要需求的满足所掩盖。

3. Rubric-to-Code定位：让token收到“精准罚单”

这是RCCA最核心的创新。评估器不仅给出标量分数，还生成诊断性文本归因：每次检测到失败时，同时输出相关的代码片段、事件处理器、状态变量、DOM区域或交互路径。

这些文本证据经过源码级关系扩展——包围函数、事件绑定、状态读写、函数调用——形成局部化的源码区间。然后将字符级区间通过tokenizer偏移映射对齐到生成token序列上，赋予不同的诊断权重：

$$w_{i,t}=\begin{cases}\bar{w}_{i,t},&A_{i}<0,\\1,&A_{i}\geq 0\ \text{and}\ t\in\mathcal{T}^{\mathrm{dir}}\cup\mathcal{T}^{\mathrm{ctx}},\\c,&A_{i}\geq 0\ \text{and}\ t\notin\mathcal{T}^{\mathrm{dir}}\cup\mathcal{T}^{\mathrm{ctx}},\end{cases}$$

直接关联的错误token权重为3.0，上下文关联token权重为1.5，其余token权重为1.0。关键在于非对称性设计：负优势样本的更新集中在诊断出的错误区域，而正优势样本不对这些区域额外强化，反而让未被诊断的代码区域收到稍强的正向更新（$c=1.2$）。这防止了模型“在正确的地方反复自我奖励”。

最终，token权重被整合进GRPO的损失函数，但不改变组相对优势和裁剪机制本身：

$$\mathcal{L}_{\mathrm{RCCA}}=-\frac{1}{G}\sum_{i=1}^{G}\frac{1}{T_{i}}\sum_{t=1}^{T_{i}}\min\Big(\rho_{i,t}w_{i,t}A_{i},\,\rho^{\mathrm{clip}}_{i,t}w_{i,t}A_{i}\Big)$$

这让RCCA成为一个“外科手术式”的RL框架：层级奖励决定了哪个采样结果更好（样本级信号），诊断权重决定了这个结果中的哪些token应该为它的好或坏负责（token级信号）。

三、实验：跨基准的“实现级”能力跃迁

RCCA被应用于Ling-3.0-Flash——一个124B参数的混合线性MoE模型，每token激活5.1B参数。训练分为三阶段：基座模型 → SFT → RCCA强化学习。

在MiniAppBench上的完整训练轨迹清晰展示了两段式增益：Ling-3.0-Flash裸模型仅9.05%，SFT后提升至26.85%，RCCA进一步推高至41.25%。这个成绩略微超越Claude Opus 4.5的41.14%，且在Hard难度子集上达到37.60%，远超Claude Opus 4.5的22.33%。

模型 平均通过率(%) Easy Mid Hard
Ling-3.0-Flash 9.05 12.94 8.99 5.49
Ling-3.0-Flash + SFT 26.85 37.41 22.45 22.44
Ling-RCCA-Flash 41.25 53.39 35.03 37.60
Claude-Opus-4.5 41.14 59.09 41.18 22.33

更值得注意的是ArtifactsBench上的跨基准泛化。RCCA模型达到76.19分，相较自身SFT模型提升4.48分，超越GPT-5的72.55分。论文特别强调，这种跨基准的提升来自“实现层面的行为学习”，而非针对特定基准的模式记忆——因为RCCA的优化信号被绑定在事件处理器、状态更新和DOM操作等通用实现模式上，而非特定题目的表面特征。

四、从Agent基础设施到模型训练的路径信号

RCCA的价值不止于一个模型分数。它展示了一条从环境反馈到训练信号的清晰转化链路：AWorld风格的交互执行框架暴露交互轨迹、需求级结果和诊断证据，RCCA将这些结构化信号转化为可优化的token级梯度权重。

这一思路的延伸空间很明确：当Agent的任务不再限于Web应用生成，而是扩展到更复杂的多步操作时，rubric级归因和代码级定位的方法论能否同样适用，是一个值得观察的开放问题。当前限制也很清楚：RCCA依赖评估器生成的文本归因质量，如果诊断本身错误，信用分配就会被误导。
