Program-as-Weights: A Programming Paradigm for Fuzzy Functions

📅 2026-07-06

12.9B参数量屠龙刀！PAW架构让0.6B小模型性能超越32B大模型，推理内存仅需1/50

一、引言

在日常开发中，开发者常常面临一类棘手问题：编写规则去实现“给重要的日志行报警”、“修复畸形的JSON数据”或“按意图排序搜索结果”等任务。这类任务难以用精确的符号逻辑编码，却对人类直觉而言十分自然。传统做法是将这类“模糊函数”外包给大语言模型（LLM）的API，但这种做法带来了高昂的成本、脆弱的依赖性和难以复现的问题。

针对这一痛点，来自滑铁卢大学、康奈尔大学和哈佛大学的研究者提出了一种颠覆性的新范式——Program-as-Weights (PAW，程序即权重)。该方法将模糊函数编译为可本地执行的小型神经程序，在FuzzyBench测试集上，仅用0.6B参数的模型执行PAW程序，性能竟超越了直接提示Qwen3-32B模型，且推理内存仅为后者的五十分之一。

二、核心方法：从“每输入调用大模型”到“每函数编译一次小模型”

PAW范式的核心思想是颠覆传统的“大模型即服务”模式，将一个庞大且昂贵的模型从一个“每次输入都要解决问题的求解器”，转变为一个“仅需每函数编译一次的工具构建器”。

1. 编译器-解释器架构

PAW系统由两个核心部分组成：一个大型的神经编译器和一个轻量级的、冻结的神经解释器。

该系统的运作流程分为两步：
1. 编译：在云端，开发者将函数规范（自然语言描述和输入输出示例）输入到神经编译器。编译器输出一个紧凑的神经程序。
2. 执行：在本地，一个冻结的轻量级神经解释器加载该程序，像执行普通函数一样处理用户输入。

数学上可以表述为：

$$p\;=\;\texttt{Compiler}(s),\qquad\hat{y}\;=\;\texttt{Interpreter}(p,x)\;\approx\;f(x)$$
  • s 是用户提供的函数规范
  • p 是编译生成的神经程序
  • x 是用户输入
  • ŷ 是系统输出
  • f(x) 是目标函数的理想输出

这个划分完美地镜像了经典编程世界：编译器将源代码翻译成可执行文件，而解释器（运行时）则执行这个文件。最大的不同在于，这里的“可执行文件”是一团学习到的参数，而“运行时”是一个神经网络。

2. 混合程序：离散伪代码 + 连续权重

PAW程序并非单一的黑盒权重，而是一个“离散-连续混合体”：

$$p\;=\;\bigl(p_{\text{discrete}},\;p_{\text{continuous}}\bigr)$$
  • 离散部分（伪程序）：由Pseudo Compiler（一个未经训练的Qwen3-4B模型）生成。它通过一个简单的提示模板，将用户粗糙的原始规范“重写”为一份清晰的伪程序，包含任务的简洁描述和少量输入输出示例。
  • 连续部分（PEFT权重）：由PEFT Compiler（一个经过训练的Qwen3-4B模型）生成。它读取原始规范和伪程序，并从其隐藏状态中直接“发射”出一个轻量级的LoRA（低秩适配）模块。

这种设计非常精妙：离散的伪程序保护了小解释器免受原始规范中拼写错误和歧义的干扰；连续的LoRA则提供了仅有文本无法实现的精细行为控制。

3. Text-to-LoRA：核心编译器细节

研究者将PAW实例化为Text-to-LoRA系统。LoRA编译器在接收到规范和伪程序后，会执行一次前向传播。随后，一个LoRA映射器（LoRA Mapper）将编译器特定层的隐藏状态转换为LoRA权重，并“热插拔”到冻结的解释器中。

LoRA权重的生成并非从零开始，而是通过线性组合一组共享的、可学习的基向量来实现：

$$A^{\text{ex}}_{l,m}\;=\;\sum_{n=1}^{N}\alpha^{A}_{l,m,n}\,A^{(m)}_{n},\qquad B^{\text{ex}}_{l,m}\;=\;\sum_{n=1}^{N}\alpha^{B}_{l,m,n}\,B^{(m)}_{n}$$

这个公式意味着，对于解释器的每一层和每个模块，LoRA映射器会动态地计算一组混合系数，然后用这些系数去加权组合一组预先训练好的基LoRA模块，从而生成针对当前任务的特定LoRA。

三、实验：小模型“逆袭”大模型

PAW的有效性在多个基准测试中得到了验证。研究者构建了FuzzyBench数据集，包含1000万个训练例子，覆盖超过800类模糊文本任务。

在10M规模的数据集上，主要实验结果如下：

方法 模型大小 推理内存 FuzzyBench准确率
Qwen3-32B（直接提示） 32B ~60 GB 68.70%
PAW（Qwen3 0.6B解释器） 0.6B ~1.2 GB 73.78%
Qwen3-14B（直接提示） 14B - 63.96%

结果令人震惊：一个仅0.6B参数的模型，通过执行PAW编译出的程序，其表现不仅超越了同系列的14B模型，甚至超越了32B的庞然大物，同时推理内存仅为后者的1/50。

研究者还测试了PAW在图像条件任务上的泛化能力，仅将文本编译器替换为多模态编译器VLM，即可处理图像输入。

在CoSyn-400K等图表理解任务上，搭载0.6B解释器的PAW系统，其性能超越了包括4B参数在内的所有视觉语言模型（VLM）基线。这证明了编译器-解释器抽象在多模态领域的巨大潜力。

四、展望

PAW论文提出了一种极具颠覆性的软件构建哲学：让大模型承担“编译”的重活，让小模型轻装执行。一个函数只需在第一次定义时调用一次大模型进行编译，之后就像调用一个库函数一样，可以在任何设备（哪怕是笔记本或浏览器）上离线、快速、零成本地反复运行。

这不仅解决了高昂的API调用成本和隐私问题，更重要的是，它真正将AI能力内化为了软件的基础构建模块。PAW程序是单一文件，支持版本控制，可以像Python模块一样分发。

想象一下，未来的软件开发可能不再是“我用大模型API来实现模糊功能”，而是“我用PAW将模糊需求编译成一个确定性的、可重用的代码库”。这也许是通往Agents大规模落地和真正“小而美”模型时代的关键一步。
