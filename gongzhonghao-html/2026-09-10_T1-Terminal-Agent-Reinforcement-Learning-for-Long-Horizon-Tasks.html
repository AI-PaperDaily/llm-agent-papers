T1: Terminal Agent Reinforcement Learning for Long-Horizon Tasks

📅 2026-09-12

腾讯与NUS联合推出T1终端智能体：122B MoE强化学习攻克长程任务，64.0%解决率超越GPT-5.4

一、引言

大模型与Agent的融合正将AI推向一个更严苛的战场：Linux终端。传统的代码补全和问答任务，模型只需输出文本即可；而终端任务要求模型发出真实命令、观察环境反馈、从部分失败中恢复，并持续执行数百步操作。一次错误的rm -rf或git reset --hard都可能造成不可逆的后果。正是这种「执行后果不可逆」的残酷特性，使终端成为检验长程Agent能力的终极试炼场。

然而，当前Agent强化学习在该领域面临两个核心瓶颈：稀疏MoE模型的训练-推理不一致（推理引擎与训练后端在token切分和专家路由上的细微差异会导致梯度指向错误的子网络），以及二元奖励信号的严重稀疏性（数百小时的沙箱执行仅换来1比特的成败反馈）。腾讯混元基础模型团队与新加坡国立大学等机构联合发布的T1模型，正是针对这两个瓶颈给出的实证回答。该论文提出TITO（Token-In, Token-Out）和R³（Rollout Routing Replay）两项机制，配合密集验证奖励设计，在Terminal-Bench 2.1上实现了64.0%的解决率，以10B激活参数超越了GPT-5.4（54.8%）和DeepSeek-V4-Flash（56.9%），逼近Claude Opus 4.7的66.1%。

二、核心方法：为Long-Horizon MoE强化学习打造的三大支柱

1. TITO：Token-In, Token-Out——消灭token级失真的根源

在异步RL训练中，采样端（推理引擎）和训练端（训练后端）是两个独立的软件栈，各自拥有不同的内核、归约顺序和张量布局。更关键的是，Agent harness在两个引擎之间只交换解析后的文本，而非token标识符。当训练端重新渲染整个对话历史时，enc(dec(a_i))这一编码-解码往返过程并非恒等变换：非规范化的token切分被丢失、模板会修剪部分内容、工具调用的空白符被重新序列化。结果就是，训练端条件化的token流与采样端实际生成的token流产生了偏移，重要性比率r_j(θ)所比较的两个分布已经不是在比较同一个策略的两个版本。

TITO的核心思想极为直接：「采样端输出什么token，训练端就训练什么token」。具体实现分为两个方向——Token-In将模板渲染和编码操作固定为每轮一次、仅追加式执行，确保前缀逐比特精确；Token-Out则将整个trial拼接为单一token流，通过对采样token施加loss mask、对工具输出和胶水token施加mask，保证梯度只流经模型实际采样的位置。在边界处，组装器按照从强到弱的四级前缀关系（精确匹配、有界修复、重token化、回退）修复边界。生产环境审计显示，loss区域内的token漂移率为0.0000%。

2. R³：Rollout Routing Replay——锁定专家路由的离散选择

对于Qwen3.5-122B-A10B这样的MoE模型，116.0B的专家参数占到了总参数的95.5%，而每个token仅激活256个专家中的8个。路由选择I_j^ℓ是一个离散的TopK操作：

$$\mathbb{I}^{\ell}_{j}=\operatorname{TopK}_{k}(\bm{s}^{\ell}_{j}),\qquad\bm{y}^{\ell}_{j}=\sum_{e\in\mathbb{I}^{\ell}_{j}}[\bm{s}^{\ell}_{j}]_{e}\,f_{e}(\bm{h}^{\ell}_{j})$$

由于TopK在离散边界处不连续，推理端和训练端浮点运算的微小差异就足以交换一个被选中的专家和它的候补者。这意味着policy被写为π_θ(·|T_{<j}, I_j)时，加载的是两个不同的子网络。

R³的解决方案同样朴素而有力：采样端在生成过程中记录每一层实际激活的专家路由掩码，训练端的前向传播强制使用这些记录的路由选择。关键在于，R³只替换路由掩码，保持softmax在实时logits上计算，因此路由器仍然可训练，计算图不受影响：

$$g^{\ell}_{j,e}=\frac{\exp([\bm{s}^{\ell}_{j}(\theta_{t})]_{e})}{\sum_{e^{\prime}\in\mathbb{I}^{\mathrm{r},\ell}_{j}}\exp([\bm{s}^{\ell}_{j}(\theta_{t})]_{e^{\prime}})}\;\;\text{for }e\in\mathbb{I}^{\mathrm{r},\ell}_{j}$$

TITO和R³联合作用的结果是，训练-推理对数概率差距从0.021降至0.013，且loss区域内token漂移为零。

3. 密集验证奖励：让失败轨迹也携带学习信号

当二元奖励「任务解决=1，未解决=0」成为唯一反馈时，那些满足了部分要求但未完全成功的轨迹全部归零。论文提出的密集验证奖励将每个断言（assertion）的通过数量作为奖励信号：

$$r = \frac{P}{S}, \qquad S=20$$

其中P为通过的断言数，S为固定全局尺度。这里有两个关键设计决策：使用绝对数量而非通过比例（通过10/20个断言与通过2/4个断言的工作量截然不同，比例会掩盖这种差异），以及固定全局尺度（避免逐batch归一化导致奖励尺度漂移，使critic的回归目标不一致）。奖励被放置在轨迹的最后一个响应token上，通过GAE（γ=λ=1）将时间信用分配回溯到整个交互序列。

三、实验：长程终端任务上的突破性表现

主要结果

在Terminal-Bench 2.1（89个held-out任务）上，T1的训练轨迹清晰展示了RL的效力。基座模型Qwen3.5-122B-A10B得分为43.8%，经过RST监督微调后达到49.4%，而三个epoch的PPO训练将分数推至64.0%。RL单独贡献了14.6个百分点，占总提升（20.2个百分点）的72.3%。换句话说，终点线附近四分之三的距离是由执行反馈驱动的强化学习而非模仿演示赢得的。

在同一测试框架下，T1超越了GPT-5.4（54.8%）、DeepSeek-V4-Flash（56.9%）、Kimi-K2.5（56.4%）和Claude Sonnet 4.6（51.5%），位居第四，紧随Claude Opus 4.7（66.1%）之后。考虑到T1的10B激活参数远小于部分对比模型，这一效率优势在模型规模与性能的散点图中尤为醒目。

长程任务泛化

在Long-Horizon Terminal Bench（LHTB）上，T1达到27.9%的平均奖励，与Gemini-3.1-Pro持平，超过GPT-5.4（27.2%）和GLM-5.1（26.7%）。在更难的Terminal-Bench Hard上，T1以38.0%的解决率超过DeepSeek-V4-Pro（36.0%）。领域分解显示，T1在debugging上达到100.0%解决率（5个任务全过），系统管理达到88.9%，这两个领域恰恰最依赖多步推理和工具使用。

训练动力学

训练过程中的行为分析揭示了一个健康的信号：平均tool-call轮次从10.4增长到20.9后趋于平稳，总序列长度从11.5k增长到17.8k后同样进入平台期。这种有界增长与长度奖励劫持的无界增长截然不同。Critic预热训练使解释方差从冷启动的-33.6提升至0.71-0.86的稳定区间，从未跌入负值。

四、展望

T1的贡献远不止一个性能数字。它证明了一件事：在真实环境中通过执行反馈进行强化学习，可以稳定地优化一个122B规模的稀疏MoE模型，并将能力迁移到与训练集完全脱节的测试任务上。论文对失败实验的坦诚记录同样宝贵——Critic校准不会自动带来策略改进、上下文管理决定Agent能学到什么、rollout吞吐量会改变训练分布——这些经验对于任何尝试在长程任务上训练Agent的研究者都是实用指南。而对于产业界，一个以10B激活参数在终端任务上超越更大规模闭源模型的开源方案，则提示了一条通往高效可靠软件Agent的可行路径。留在桌面的问题是：TITO和R³的组合能否迁移到完全异步训练场景？密集验证奖励的设计原则在其他环境（浏览器、代码库级操作）中是否依然成立？这些答案，或许决定了RL驱动的Agent post-training能走多远。
