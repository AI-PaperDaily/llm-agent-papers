Agent-R^2: Scaling Agents for Realistic Productivity Work via Real-Source Data Synthesis

📅 2026-11-15

浙大与百度联手训练4B Agent：GDPval达到51.0%！

一、引言

让Agent写一份办公报告，难点往往不是生成文字，而是找到正确的附件、读懂表格、处理缺失数据，再把计算结果做成可交付的文件。只要其中一步出了错，一份格式漂亮的报告也可能毫无实际价值。

现有训练数据常把工具调用、文档问答和文件生成分开处理，较少覆盖从真实工作目标到最终交付物的完整过程。浙江大学与百度提出的 Agent-R 2，试图从数据源解决这个问题：从真实职业活动和网页语料中提取工作流程，检索真实文件，再合成带有细粒度评分标准的任务，用于训练Agent。

这项工作值得关注的重点，不只是小模型的分数，更是它如何让模型减少“跳过证据、直接交差”的行为。

二、核心方法

Workflow Extraction与Attachment Searching：从真实来源构建任务环境

Agent-R 2 的数据流水线分为工作流提取、附件搜索和任务合成三个阶段。它们并非各自生成一份材料，而是逐步把职业活动、文件上下文和交付要求连接起来。

首先，系统从 O*NET职业活动种子出发，将网页语料的学科信息映射到职业类别，再由合成模型筛选出既包含工作流程、又涉及文件操作的文本。符合条件的内容被整理成工作流蓝图，记录信息依赖、所需文件类型和预期产出。

接下来，系统根据蓝图多轮搜索公开文件。它先检查搜索结果的标题和摘要，再下载候选文件，通过命令行和图像查看工具检查封面、目录等关键内容。只有能够共同满足工作流信息与操作需求的文件集合，才进入下一阶段；超过50页或大于2 MB的文件会被丢弃。

这一步的价值在于保留真实文件的复杂性：不同格式可能有不同布局，信息可能分散在多个附件中，文件本身也未必完整。Agent因此需要处理更接近实际办公环境的证据，而不只是读取一份结构整齐的模拟文档。

Task Synthesis：让任务、附件与评分标准相互对应

拿到工作流和候选文件后，合成模型在沙箱中检查文件内容：分页文件会被渲染成页面图像，电子表格则被解析为工作表级表格，同时保留原文件供进一步查看。必要时，模型还会搜索和获取网页证据。

随后，模型确定哪些文件作为求解附件，并共同设计两项内容：

  • 用户指令：规定需要完成什么工作、生成什么交付物。
  • 评分标准（Rubric）：把证据依据、分析正确性、结构和格式等要求拆成可检查的条目。

为了给训练和评估提供参照，系统再让 Claude-Opus-4.5 在沙箱中完成任务，保存其工具操作轨迹和生成文件。验证环节会检查参考文件是否满足评分标准：如果未满足的条目缺少附件支持或与指令不符，就修订评分标准；如果条目合理，则要求专家模型修改交付物一次。

最终，系统从1万个网页语料候选中得到4千条任务。每条任务平均包含2.51个附件和15.3项评分标准；专家轨迹平均有18.0步、41.8k token，体现了从查证到文件构建的多步过程。

Rubric-Based Reinforcement Learning：从模仿操作转向优化交付质量

训练以 Qwen3-4B-Thinking-2507 为基础，分成两个阶段：先用3千条任务对应的专家轨迹进行监督微调（SFT），学习检查文件、调用工具和制作交付物；再用不重叠的1千条任务进行基于评分标准的强化学习（RL），优化最终结果。

RL阶段使用GRPO算法，让模型在持久化沙箱中完成多轮操作。完成后，PDF、PPTX和DOCX被渲染为图像；XLSX则转换为包含重新计算数值、公式和页面图像的表示，由 Qwen3.6-Plus 对照评分标准及参考文件打分。

奖励只看结果，不针对中间工具调用错误设置显式惩罚：

$$ r=\begin{cases} 0,&\text{if }\hat{\mathcal{F}}_{d}=\emptyset,\\ \dfrac{\operatorname{Score}(\hat{\mathcal{F}}_{d},\mathcal{F}_{r},\mathcal{R})}{\text{max score}},&\text{otherwise}. \end{cases} $$

这意味着，没有生成交付文件时奖励为零；有交付文件时，奖励取其相对于满分的评分比例，模型需要通过最终成果质量获得回报。

三、实验

实验分别考察生产力任务和文档问答。GDPval要求Agent依据任务生成交付物，并按评分标准评测；OfficeQA使用Markdown形式的办公源文件，考察文档证据理解与回答能力。两个基准的最大操作步数均为100步；GDPval使用Gemini-3.1-Pro作为评估模型。对于Qwen文本模型，图像查看调用由同系列、同量级的多模态模型辅助处理。

模型 GDPval Pass@1 OfficeQA Pass@1
Qwen3-4B-Thinking-2507 32.4% 2.2%
Agent-R 2-4B-SFT 45.3% 11.4%
Agent-R 2-4B 51.0% 14.8%
Qwen3-235B-A22B-Thinking-2507 48.0% 13.8%

表中 Pass@1 对应单次尝试的结果：GDPval评估交付物，OfficeQA判断回答是否正确。在GDPval完整集合上，Agent-R 2-4B比其基础模型提高18.6个百分点，也高于所比较的Qwen3-235B-A22B模型。结果同时显示，SFT和后续RL各自带来了增益，但这并不代表4B模型在所有任务上都优于更大模型。

更有解释力的是行为变化。研究将Agent尚未充分查证、构建或验证，就输出表面合理成果的现象称为捷径行为。在行为分析中，基础模型平均只有6.7次工具调用，SFT后增加到39.0次；与此同时，平均错误数从2.88增至16.3，完成率从86.8%降至78.2%。这说明更积极的探索并不自动等于更可靠的完成。

加入RL后，平均工具调用为33.1次，平均错误降至12.9次，完成率升至90.9%。在GDPval的捷径行为分析中，对符合统计条件的任务，交付物复查率从基础模型的0.5%升至RL模型的95.8%；在相应错误事件中，未修复错误便继续写交付物的比例从55.0%降至11.0%。

消融实验也支持数据和奖励设计的作用：在同源匹配的1千条SFT任务上，使用真实文件的模型GDPval Pass@1为43.3%，使用合成文件时为41.4%；从同一SFT模型出发进行RL，使用评分标准奖励得到51.0%，移除该奖励后为49.5%。

在材料测试报告案例中，基础模型未找到目标表格数值，却仍用虚构证据生成报告；Gemini-2.5-Pro虽然进行了更多检查，但关键测量值被转成NaN，导致图表为空。Agent-R 2-4B则从解析、计算和绘图错误中恢复，算出所需硬度值，并检查最终PDF中的图表。
