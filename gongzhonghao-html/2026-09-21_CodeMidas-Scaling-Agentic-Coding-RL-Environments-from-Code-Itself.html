CodeMidas: Scaling Agentic Coding RL Environments from Code Itself

📅 2026-09-23

小米联手北大港大发布CodeMidas：让源代码自动变成RL训练环境，DeepSWE提升11.7%

大模型编码智能体在真实软件工程任务中的能力，正越来越依赖强化学习。但强化学习需要两样东西：足够多样化的任务，以及可靠的奖励信号。现有编码 RL 环境大多从 issue、PR、commit、已有测试或文档中提取任务，覆盖范围天然受限于这些“开发记录”的存在。小米、北京大学、香港大学等机构的研究者提出 CodeMidas，直接从开源代码库的已实现功能出发，把源代码本身转化为可执行的 RL 训练环境。论文显示，训练后的模型在 DeepSWE 上的通过率从 10.0% 提升到 21.7%。

一、核心方法：把已有代码点石成金

CodeMidas 的输入只有源代码，不需要 issue、PR、commit、既有测试或书面描述。整个流水线分为四个模块：任务设计与代码库改造、执行锚定的测试构建、环境准备与执行一致性检查、基于 rollout 的后过滤。

1. 任务设计与代码库改造

智能体首先分析项目结构和构建元数据，识别具有公共入口与可观察行为的已实现功能。这些功能可以是命令行工具、纯库函数，也可以是有状态的库 API。对每个候选任务，智能体会追踪公共入口和共享依赖，界定任务范围，然后删除核心实现，保留项目结构、依赖和共享组件，形成一个真实但有待补全的开发起点。

任务语句明确输入、可观察行为和所需公共接口。原始实现被单独保留，作为该任务的参考解决方案。论文没有把内部实现写入要求，求解者可以自由选择内部辅助函数和算法。

2. 执行锚定的测试构建

测试不是凭空生成，而是以原始代码的实际执行结果为依据。智能体根据任务语句映射测试输入和边界情况，在参考代码库中调用公共入口，记录真实输出。对 CLI 工具，测试通过命令执行；对纯函数，测试通过输入输出样例；对有状态 API，测试通过多轮调用序列验证依赖关系、顺序和清理行为。

训练时采用如下二进制执行奖励：

$$r = \mathbf{1}(\text{提交实现通过隐藏验证器})$$

审阅智能体还会检查每条断言是否被任务语句支持。若断言依赖私有符号且没有行为替代，任务会被拒绝。这样可以减少“测试过于严格”或“测试泄露实现细节”的问题。

3. 环境准备与执行一致性

环境准备从统一基础容器开始，智能体根据项目声明安装依赖、准备构建和运行时资源。清理步骤会删除可能暴露已删除实现的编译产物、缓存和构建文件，同时移除与目标功能相关的原始测试。训练求解时，验证器被放在求解环境之外，仅在评分阶段注入，返回二进制执行奖励。

执行一致性检查要求在六个全新容器中验证状态转换：两个起始代码库运行必须失败，四个参考实现运行必须通过。这种重复检查用于确认任务具有预期的 fail-to-pass 结构，并筛除执行结果不稳定的环境。

4. 基于 rollout 的后过滤

执行一致性只覆盖起始态和参考解。CodeMidas 在 RL 训练前还会用智能体 rollout 进一步过滤：

  • 泄露过滤：攻击性 rollout 会刻意搜索编译产物、缓存、遗留文件和已安装副本，并记录可疑漏洞。独立审阅确认泄露材料是否能绕过预期开发工作，若可绕过则排除任务。
  • 智能体解一致性：编码智能体对每个任务尝试四次，审阅智能体结合轨迹、提交代码、测试输出和参考解，判断验证器是否产生假阳性或假阴性。
  • rollout 结果过滤：前沿模型对每个任务进行多次尝试，只保留既有成功又有失败的任务，避免所有尝试都失败或都通过带来的弱信号。

最终数据集包含 5,545 个训练任务，来自 3,185 个开源代码库，覆盖 23 种编程语言和 15 个技术领域。参考补丁中位数为 142 行，65.9% 的任务至少涉及两个源文件。

二、实验：一次性涨满五类外部基准

研究者用 CodeMidas 任务对 MiMo-V2.5 进行 GRPO 训练。验证器提供二进制执行奖励，每个任务 32 次 rollout，batch size 为 32。

结果显示，RL 训练后所有五个外部基准全部上涨：

基准 初始分数 CodeMidas RL 绝对提升
DeepSWE 10.0% 21.7% +11.7%
Terminal-Bench v2.1 63.7% 72.2% +8.5%
ProgramBench Almost Solved 4.5 21.5 +17.0%

这些任务覆盖 issue 修复、整程序构建、代码翻译和终端工作，说明从源代码提取的功能任务具备跨任务类型的迁移价值。在 CodeMidas Val 上，通过率从 35.0% 提升到 44.7%，同时轨迹总长度增加，说明模型更充分地利用了交互预算。

三、任务规模与质量：5k 高质量样本胜过 8k 未过滤样本

论文还做了规模与质量消融。研究者分别从高质量数据集中随机抽取 1k、3k 和完整 5k 任务，并与一个未做清理、未做执行一致性检查、未做后过滤的 8k 原始样本对比。训练配置完全一致。

结果显示，随着高质量任务数量增加，DeepSWE 分数从 17.57 升到 19.05，再到 21.70；CodeMidas Val 从 41.30 升到 43.22，再到 44.73。更重要的是，高质量 5k 池在 SWE-bench Pro、DeepSWE 和 CodeMidas Val 上均超过未过滤的 8k 样本，分别高出 0.59、4.59 和 4.49 个百分点。甚至 3k 高质量子集也在三项评估上超过 8k 未过滤样本。

这说明环境可靠性和训练适配性，比单纯堆任务数量更关键。

四、行为变化：模型开始主动探索和自验

研究者进一步分析了 RL 训练前后智能体的行为变化。早期和后期 rollout 对比显示：

  • 代码库探索：首次编辑前的 read/search 调用从 27.2 升至 40.1；
  • 代码草稿：写入代码片段此前出现在推理中的比例从 0.358 升至 0.629；
  • 自我验证：最终仓库编辑后的不同验证命令从 2.03 升至 2.53。

在 CodeMidas Val 上，同一任务、同一 checkpoint 内，带智能体自写验证的 rollout 平均通过率高 4.2 个百分点。外部基准同样观察到泛化：SWE-bench Pro、ProgramBench 和 Terminal-Bench 上的代码库探索次数均增加，SWE-bench Pro 与 ProgramBench 上的代码草稿比例也明显提高。

五、展望

CodeMidas 展示了一条从“已有代码库”直接扩容编码 RL 环境的可行路径。它不依赖 issue、PR 或文档，也不受已有测试覆盖率限制，因此可以在更多语言、更多软件工程任务中复制。未来若能进一步降低构建流水线的算力开销、提升跨语言和跨领域的验证鲁棒性，源代码本身将成为编码智能体持续进化的高质量燃料。
