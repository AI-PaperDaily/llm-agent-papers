Realtime-Venus: A full-duplex interaction system with asynchronous delegation

📅 2026-09-24

蚂蚁×清华发布Realtime-Venus：双9B全双工语音系统，StreamingBench 70.2%领跑在线模型

一、当对话不再“回合制”：全双工交互的工程挑战

在真实的人类对话中，听者不会等对方说完再回应。一个轻微的点头、一句“嗯”、甚至一声背景噪音，都可能影响说话者的表达策略。对语音交互系统而言，真正的挑战不在于“听懂一句话”，而在于在持续说话的同时，判断何时停下、何时继续、何时启动后台任务。

现有大模型在全双工交互上存在明显短板：要么依赖语音活动检测做粗粒度的“二值判断”，无法区分“打断”与“附和”；要么把工具调用硬塞进前台对话流，导致响应延迟和上下文错位。

论文提出的 Realtime-Venus 系统由蚂蚁集团与清华大学联合研发，包含两个分别训练的 9B 模型——Realtime-Venus-Omni（音视频全双工交互）和 Realtime-Venus-Audio（纯语音全双工交互），以及一个异步执行框架 Realtime-Venus-Harness。该系统在 StreamingBench 上达到 70.2%，在 Full-Duplex-Bench v1.5 上对用户插话的响应率达 75%，并在回话（backchannel）场景下实现 97% 的继续率，超越 Gemini 3.1 Live 和 GPT-4o。

二、核心方法：三个层面的系统性创新

2.1 双 9B 前端模型：感知、控制与生成的一体化

Realtime-Venus 的两个前端模型均继承自 MiniCPM-o 4.5 的 Omni-Flow 架构。Realtime-Venus-Omni 使用 SigLIP2 编码视频帧、Whisper-Medium 编码音频，两者对齐后送入 Qwen3-8B 语言主干；Realtime-Venus-Audio 则去除视觉分支，仅处理流式音频。语言主干生成文本和隐藏状态，隐藏状态进一步条件化离散 S3 语音 token 的预测，最终由流式 flow-matching 解码器合成波形。

实时推理按 1 秒为单位分块。每个 chunk 内，模型预测状态 token：

  • <|listen|>：继续感知，不发言
  • <|speak|>：正在生成语音
  • <|turn_eos|>：结束当前轮次

这一设计的核心价值在于：对话控制、文本生成、语音生成共享同一个语义表征，使得声学上相似的重叠语音（如“嗯”与“打断我”）能够产生截然不同的行为。短促的“嗯”属于 backchannel，模型保持 <|speak|> 继续原计划；真正的打断则触发 <|turn_eos|>，终止未说出的部分，重新规划回应。

2.2 统一流式序列化：把交互建模为因果时间线

论文的关键设计是将用户流、助手流、后台流三类信息，放到同一条因果时间线上进行序列化建模。用户流是连续到达的感知特征；助手流包含前台文本、S3 语音 token 和可选的委派指令；后台流是异步返回的外部计算结果。

三流在同一个 LLM 中交织成单一 token 序列。训练时，文本和语音 token 按实际起始时间分块，模型学习到历史依赖的交叉模式。推理时，文本发射速率与语音播放进度对齐：

$$n_{k}=\arg\min_{n}\left|\tau_{k-1}+\mathcal{D}(Y_{k,1:n})-t_{k}\right|$$

其中 $\tau_{k-1}$ 表示此前已调度语音的结束时间，$\mathcal{D}$ 是前 $n$ 个候选文本 token 的估计时长。该公式让生成节奏跟随真实时钟，确保“说的”和“听到的”处于同一时间轴。

2.3 异步委派：前后台解耦的执行框架

Realtime-Venus 的核心架构创新是 双循环运行时。前台的交互循环持续处理媒体输入，维持流式语音输出；后台的能力循环处理委派任务，执行外部工具或长时推理。

委派通过私有 token 通道完成——模型在 token 流中生成 <delegate> ... </delegate> 包裹的自然语言请求，该内容对用户不可见。Harness 在请求边界执行因果任务捕获，固定证据快照：

$$X_{i}=\operatorname{Snap}(\mathcal{B}^{\sigma};\kappa_{i},\Delta)$$

这一设计的精妙之处在于：后台任务基于发起时的证据运行，但结果返回后，前端根据当前的对话状态决定如何措辞和何时说出来。任务执行期间，前端持续感知用户的新输入——如果用户中途改变了意图，前端可以灵活调整对返回结果的表达方式，或者将其延后处理。

2.4 长视频记忆：小时级会话的无训练方案

流式音视频输入的 token 数量随时间线性增长，而 Qwen3-8B 的上下文窗口有限。论文提出了一种免训练的外部记忆模块，核心机制包括：

  • 记忆门控：基于运动补偿预测代价决定是否归档当前帧，避免冗余存储
  • 检索评分：使用 MaxSim 算子做 token 级匹配，结合 MAD 加权和 MMR 相关性-多样性平衡，筛选相关帧
  • 上下文重组：将检索到的历史帧与其邻接音频按时间顺序拼接，与近期窗口一同送入生成阶段

这一模块使 Realtime-Venus-Omni 在 60-90 分钟的 LVOmniBench 子集上准确率提升 5.88 个百分点。

三、实验数据：全双工持续性领跑在线模型

3.1 音视频理解：六项基准的在线模型最佳

Realtime-Venus-Omni 在 StreamingBench（70.2%）、OVO-Bench（64.7%）、Daily-Omni（81.3%）等六项视频基准上领先所有在线模型。相较于 MiniCPM-o 4.5 基座，StreamingBench 提升 2.3 个百分点，OVO-Bench 提升 4.0 个百分点。值得注意的是，StreamingBench 和 OVO-Bench 恰恰是最接近真实实时交互场景的评测集，突显了全双工训练策略对理解能力的正向迁移。

Realtime-Venus-Audio 在音频理解上同样表现突出：MMAU 达 78.0%，MMAU-Pro 达 63.2%，为对比模型最高；在 Llama Questions（83.8%）和 Speech CMMLU（67.8%）上领先。AlpacaEval 得分为 4.81，并列最优。

3.2 全双工交互：区分“继续”与“打断”

Full-Duplex-Bench v1.5 的四维测试揭示了全双工模型最核心的能力——区分不同功能的重叠语音。Realtime-Venus-Audio 在用户回话（97% 继续率）、面向他人说话（88% 继续率）、背景语音（86% 继续率）三项指标上均领先 Gemini 3.1 Live 和 GPT-4o。GPT-4o 在“面向他人说话”场景的继续率仅为 2%，几乎每次都误判为打断。

用户打断场景下，Realtime-Venus-Audio 的响应率为 75%，高于 MiniCPM-o 4.5 的 60%，但低于 Joy-Duplex 的 88%。这提示模型在“坚决保持”与“果断止步”之间仍存在微妙的平衡空间。

场景 Realtime-Venus-Audio GPT-4o Gemini 3.1 Live
用户打断（应响应） 75% 78% 77%
回话（应继续） 97% 70% 95%
面向他人（应继续） 88% 2% 66%
背景语音（应继续） 86% 4% 66%

3.3 委派决策：两个前端的不同性格

内部委派基准测试揭示了有趣的模型个性差异：Realtime-Venus-Audio 对外部能力请求的委派召回率高达 92.22%，但常把本应直接回答的日常请求也丢给后台（非委派特异性仅 39.44%）；Realtime-Venus-Omni 则更克制，非委派特异性 84.44%，但委派召回率仅 68.33%。这一差异反映了多模态训练数据对模型“任务边界感”的塑造作用。

四、技术价值与开放性思考

Realtime-Venus 的贡献不在于又刷新了几个榜单，而在于证明了一个统一的流式公式可以同时承载感知、对话控制和异步计算。双循环架构将“前台的人机交互相应”与“后台的能力扩展”彻底解耦，这为语音 Agent 在真实场景中的规模化部署提供了工程参考。

当前系统仍依赖 1 秒 chunks，对秒内快速事件的捕捉粒度有限。论文的后续方向——更细粒度的流式分块、更长的上下文窗口、多步工具调用中的并发管理——指向了一个更本质的问题：当模型在说话时，它的“思考”和“倾听”能否真正同步进行？这或许是全双工交互系统走向成熟的最后一道门槛。
