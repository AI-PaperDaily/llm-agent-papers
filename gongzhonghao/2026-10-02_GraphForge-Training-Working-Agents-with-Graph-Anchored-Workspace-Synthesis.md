## 中科大等提出GraphForge：用证据图谱合成真实文件训练数据，27B模型GDPVal提升65.7分

当大模型智能体从“对话”走向“实际工作”，一个核心瓶颈逐渐浮现：如何为工作型智能体合成高质量的训练数据？工作型智能体需要读取真实文件、协调工具、产出可交付成果，但现有数据合成管线要么生成的文件缺乏真实性与多样性，要么基于真实文件却缺少任务特定的验证器，导致结果质量无法系统检查。论文 **GraphForge** 针对这一双重难题，提出了基于**证据图谱**的训练数据合成框架，在真实文件基础上同时锚定任务与验证过程。在 GDPVal、Workspace-Bench-Lite 与 SpreadsheetBench II 三项工作型智能体基准上，基于 GraphForge 数据微调的 Qwen3.6-27B 分别取得 **1445.7 分（+65.7）**、**63.7 分（+7.7）** 与 **24.0 分（+13.7）** 的显著提升。

## 一、问题：工作型智能体训练数据的双重约束

与通用工具调用或软件工程智能体不同，工作型智能体面临的任务通常横跨文件系统、数据库与终端，要求模型读懂数十份真实文件、协调多个工具，并产出可供他人使用的交付物。训练这类智能体需要两类能力同时成立：**任务建立在真实文件之上**，且**结果可验证**。

近期的两条代表性管线各有短板。**EnvCraft** 用模型生成文件并配以 Python 脚本检查工作区状态，但脚本无法读取文件内容，可能遗漏文档交付物中的错误。**NexForge** 在真实文件上构建任务，却未提供任务特定的评价标准或验证器，结果质量无法系统检查。论文提出 GraphForge，让**任务与验证都从真实文件中的证据图谱派生而来**，填补了这一空白。

## 二、核心方法：五大阶段的证据图谱合成管线

GraphForge 将职业任务种子转化为可验证训练轨迹，包含五个阶段。设计核心是**种子与文件扮演不同角色**：种子固定任务方向以控制多样性，而具体任务与验证信号只有在真实工作区实例化之后才从文件中派生。

### 2.1 O*NET锚定的任务形式种子

种子的来源是美国劳工部 O*NET 数据库，包含职业、任务陈述与详细工作活动（DWA）的受控词汇表。经过 AI4Work 的 DIGITAL 标注过滤后，保留 246 个职业、891 个 DWA 任务类型与 3,419 个有效职业-任务类型对。每个种子是一个六元组：

$$s_{i}=(o_{i},a_{i},w_{i},p_{i},u_{i},e_{i}^{\mathrm{occ}})$$

为避免语料集中在高频职业或泛化的分析任务上，种子选择采用**边际覆盖**策略。设 $\mathcal{D}$ 为维度集合，$n_{d}(v)$ 为已选种子中维度 $d$ 上取值为 $v$ 的数量，候选种子 $s$ 的增益定义为：

$$\Delta(s\mid\mathcal{S})=\sum_{d\in\mathcal{D}}\frac{1}{1+n_{d}(v_{d}(s))}$$

该公式实现贪心选择：在某一维度上尚未充分覆盖的候选获得更高增益，从而保持职业部门、执行模式与输入文件家族的多样性。

### 2.2 真实文件工作区与证据图谱

种子是“案例中立”的，只规定谁做什么工作、解决什么需求、以何种方式执行，并不指定具体的公司、事件或数据集。搜索智能体据此寻找一个连贯的公开案例，下载所需文件形成工作区 $W_{i}=\{f_{i1},\dots,f_{im}\}$。每份文件被赋予一个隐藏角色 $\rho(f)\in\{\text{core},\text{supporting},\text{confuser},\text{ambient}\}$，分别是核心文件、支持文件、干扰文件与环境文件。这些角色指导组装但从不展示给工作智能体。

在此之上，模型构建一个**证据图谱** $G_{i}=(V_{i},E_{i})$。节点 $v\in V_{i}$ 记录源文件、其提供的事实或字段、在任务中的角色；边 $e\in E_{i}$ 记录解释、比较、协调或推导信息所需的跨文件依赖。重要的是，图谱并非“真值”，而是必须能从原始文件中恢复的中间表示。

### 2.3 证据锚定的可验证 Rubric

图谱被编译为任务规范 $\mathcal{C}_{i}=(q_{i},\mathcal{D}_{i},\mathcal{R}_{i}^{+},\mathcal{R}_{i}^{-};G_{i})$，包含任务陈述 $q_{i}$、交付要求 $\mathcal{D}_{i}$、正标准 $\mathcal{R}_{i}^{+}$ 与负惩罚标准 $\mathcal{R}_{i}^{-}$。每个正标准是一个六元组：

$$c_{k}=(d_{k},r_{k},z_{k},w_{k},A_{k},\phi_{k})$$

其中 $A_{k}\subseteq V_{i}$ 是**证据锚点**，即验证该标准所需检查的文件集合；$\phi_{k}$ 是验证程序。这一设计将执行与验证分离：工作智能体只看到任务陈述与交付要求，法官则接收锚点与验证指令，知道该检查哪些文件与交付物的哪些部分。

### 2.4 执行条件的一步修订与轨迹准入

静态检查无法捕捉长程任务中的全部歧义，因此每个初始任务规范先用强教师模型执行一次，生成初始轨迹 $\tau_{i}^{0}$ 与交付物。修订智能体随后接收原始文件、证据图谱、完整任务与 rubric 以及该次执行，检查任务是否自然可执行、所需量是否受支持、每条标准是否正确锚定、验证指令是否足以检查工件。修订智能体只返回需要修改的组件，编译器保留所有未触及字段并验证引用完整性。修订后的轨迹选择遵循：

$$\tau_{i}=\begin{cases}\tau_{i}^{0},&H(q_{i}^{1})=H(q_{i}^{0})\ \text{and}\ \tau_{i}^{0}\ \text{exists},\\[2.0pt]
\pi_{T}(W_{i},q_{i}^{1}),&\text{otherwise},\end{cases}$$

最终，轨迹只有在确定性检查确认交付物落盘、格式可读、所需表格与公式存在之后才被准入。证据锚定法官依据锚点文件与产出工件对每条标准打分，质量分数为：

$$Q_{i}(\tau)=\frac{\sum_{k\in\mathcal{R}_{i}^{+}}w^{+}_{ik}\,a_{ik}(\tau)-\sum_{j\in\mathcal{R}_{i}^{-}}\lambda_{ij}\,v_{ij}(\tau)}{\sum_{k\in\mathcal{R}_{i}^{+}}w^{+}_{ik}}$$

其中 $w^{+}_{ik}>0$ 为正标准权重，$a_{ik}\in[0,1]$ 为需求满足比例，$\lambda_{ij}>0$ 为负标准惩罚强度，$v_{ij}\in[0,1]$ 为违规程度。

## 三、实验：三项基准全面验证

SFT 语料包含 **2,169 条准入轨迹**（$Q_{i}(\tau_{i})>0.90$），从 3,638 个物化任务中筛选而来。语料覆盖 466 个不同 O*NET 任务类型、16 个职业部门中的 15 个、全部 16 种执行模式，体现了覆盖驱动的种子选择的有效性。平均每条轨迹含 50.0 步助手动作与 162.0k tokens。

![图3：2,169条SFT语料中助手步数与token化长度的分布](https://arxiv.org/html/2609.38923v1/joint_coverage.png)

在 GDPVal-AA（220 任务黄金子集）上，SFT 使 Qwen3.6-27B 在 OpenHands 支架下从 1380.0 提升至 **1445.7 Elo（+65.7）**，在 Codex 支架下从 1364.0 提升至 **1427.4（+63.4）**。Qwen3.6-35B-A3B 的提升更为显著，分别达到 **+101.7** 与 **+101.4 Elo**。在 Workspace-Bench-Lite 上，27B SFT 模型在 Claude Code 下达到 63.7（+7.7）。在 SpreadsheetBench II 上，35B SFT 模型提升 16.5 分，27B 提升 13.7 分。值得注意的是，所有训练轨迹均由 Codex 支架生成，而提升在 OpenHands、Codex、Claude Code 三个评价支架上均成立，说明语料传授的是**可迁移的工作技能而非支架特定习惯**。

论文进一步检验了**基于 rubric 引导的拒绝微调**（RFT）。在相同的 462 个查询与候选池上，三种选择策略的比较显示：锚定选择在 Workspace-Bench-Lite 与 SpreadsheetBench II 上增益最大，随机选择全面最弱，而未锚定选择在 GDPVal 上点估计更高但统计上无法区分。消融中的法官敏感性实验显示，删除某标准引用的工作表使其对应分数下降 0.377，而非目标标准平均变化仅为 0.016，表明证据锚定法官确实读取了引用的证据文件。

## 四、展望：从真实证据到可验证工作智能体

GraphForge 的核心贡献在于将任务生成与验证生成统一到同一证据图谱上，使得“做什么”与“怎么查”在源头一致。随着语料规模扩大与更强的合成模型引入，该方法有望覆盖更多任务家族与文件类型。对于正在构建工作型智能体的团队而言，这条“真实文件 + 证据锚定 + 可验证 rubric”的管线提供了一条可复现的路径。
