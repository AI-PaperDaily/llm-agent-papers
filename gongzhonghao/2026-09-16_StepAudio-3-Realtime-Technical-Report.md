# 阶跃星辰发布StepAudio 3 Realtime：边想边说架构，全双工对话98.9分

## 一、引言

实时语音交互系统长期面临一个核心困境：深度推理需要时间，但流畅对话要求即时响应。当用户请求复杂任务时，模型若等待完整推理完成再开口，会破坏自然的对话节奏；若立即回应，又可能牺牲回答质量。更棘手的是，真实对话中充满停顿、打断、背景音和未完成句——如何判断“嗯”是认同还是话说到一半的思考，决定了全双工系统的体验上限。

阶跃星辰Audio团队发布的StepAudio 3 Realtime针对这一挑战给出了系统化方案。该模型基于约196B总参数、11B活跃参数的MoE架构，将感知、推理、语音生成与工具调用组织为一个连续的listen-converse-think-act循环。报告数据显示：全双工对话基准Overall得分98.9，位列所有基线之上；音频理解基准MMSU达到90.6分；$\tau$-Voice智能体任务成功率达56.0%。这些数字背后，是**Seamless Duplex**、**Think-While-Speaking**与**Deep Perception**三个关键机制的系统设计。

## 二、核心方法

### 2.1 系统架构：连续对话循环

StepAudio 3 Realtime的系统设计围绕一个核心认知：对话中的听、说、思、行不是串行阶段，而是持续并行的状态。用户语音、模型语音、工具结果可以在对话的任何时刻到达，系统需要实时判断是否继续聆听、是否开始回应、是否深化推理、是否触发外部动作。

模型采用混合专家架构，语言骨干基于Step 3.7 Flash，音频前端使用Qwen3-Omni的Audio Transformer编码器。全双工输入路径同时接收用户音频流与模型自身音频流，经编码器和适配器映射到语言模型表征空间。生成器输出流式模型语音，该输出又回到模型音频流中，为后续的对话楼层管理提供上下文。训练管线分为模态对齐、多模态混合训练和冷却三阶段，总计处理1.2T训练token，序列长度32K，中训练阶段进一步扩展到128K上下文。

![图2：StepAudio 3 Realtime的系统架构图](https://arxiv.org/html/2609.14005v1/stepaudio3-realtime-system-architecture.png)

### 2.2 Seamless Duplex：对话楼层管理

判定何时说话、何时让出话语权，是全双工语音交互最微妙的技术难题。用户说“right”可能是一个简短的确认，也可能是即将纠正前的过渡词；一句话中间的320ms静默，是句内暂停还是话轮结束？这些判断必须综合声学证据与对话上下文才能可靠完成。

StepAudio 3 Realtime将音频组织为320ms的时序块，每块后附加状态token或文本token。系统同时接收用户语音流与模型自身语音流，结合对话历史进行上下文感知的楼层管理。模型需要区分四组信号：句内暂停与话轮结束、简短确认与实质性打断、对话目标语音与背景对话、继续发言与主动让出。训练上，中训练阶段引入了超过10,000小时的合成全双工交互数据，涵盖流式ASR、语音活动检测和话语完整性预测；后训练阶段使用高质量交互数据细化回传通道处理、打断响应和背景语音拒绝能力。

### 2.3 Think-While-Speaking：边想边说的并行推理

传统语音助手的响应模式是串行的：先完成全部推理链，再开始生成语音。这种模式在复杂问题上会导致不可接受的延迟。Think-While-Speaking的核心思想是：推理不必先于语音全部完成，语音输出可以在推理链生成过程中动态启动。

该机制使用同一音频模型的两次并发调用：**Formulation Brain**生成私有推理链，**Articulation Brain**根据当前可用的部分推理结果，以短片段方式持续输出语音。播放感知调度器根据流式音频进度释放响应片段，当推理完成后，剩余响应使用完整的推理状态。系统默认采用Speak-First策略，无需等待初始推理前缀即可开始响应，也可切换为Think-First模式等待短推理前缀。

Adaptive Thinking控制是否调用显式推理。实验表明，显式推理并非对所有话轮都必要——强制无思考条件在忠实度类别中仅比完整思考低1.72分，而在推理类别中差距达11.37分。研究者构建了基于配对判断的推理选择策略：对每个话轮，对比有思考和无思考两条轨迹的输出质量，由盲评者打分，据此标注该话轮是否需要推理。最终系统在51.5%至82.0%的不同类别话轮上调用显式推理。为加速私有推理，系统使用MTP3/MTP5多token预测，MTP5在典型接受策略下每步接受2.153个草稿token，带来最高2.05×的墙钟加速。

### 2.4 模型合并

为集成多轮对话、音频理解、通用文本推理等互补能力，研究者训练了多个参数对齐的专门化教师模型，并通过加权参数平均进行合并：

$$\theta_{\mathrm{merge}} = \sum_{i} \alpha_i \theta_i$$

其中 $\alpha_i \geq 0$ 且 $\sum_i \alpha_i = 1$。报告模型采用四教师 $3{:}1{:}1{:}1$ 权重。合并模型在音频理解上达到81.3宏平均，在通用文本上达76.5，在对话上达73.0，整体实现了平衡的能力整合而非单点最优。

## 三、实验

### 3.1 音频理解与ASR

StepAudio 3 Realtime在八个音频理解基准中的四个上领先。MMSU得分90.6，比最强基线Gemini 3.1 Pro高出7.0分；MMAR得分86.5，领先4.8分。在Step-Caption和MTalk-Bench上也位列第一，显示出对说话人属性、副语言线索和环境声的非词汇信息捕捉能力。不足之处同样明显：AudioMultiChallenge得分49.3，落后Gemini 3.1 Pro达17.7分。

一项数据消融实验尤其值得关注：使用约10万条高质量标注数据替代约200万条随机采样数据后，MMSU从78.78提升至89.70，MMAR从74.70提升至84.50——数据质量对能力提升的作用远超数据量本身。

### 3.2 全双工交互

在Artificial Analysis的Full Duplex Bench评估中，StepAudio 3 Realtime取得98.9的Overall分数，超越Qwen Audio 3.0 Realtime Plus的98.4和GPT-realtime-2的95.3。分类别来看，话轮接取得满分100.0，用户打断处理99.0，暂停处理98.9，回传通道处理98.0。这一成绩表明系统在尊重句内暂停与响应话轮结束之间、在响应用户打断与延续回传通道之间，都实现了较好的平衡。

### 3.3 对话推理与Agent任务

在StepAudioChat基准的推理模式评估中，模型取得73.0宏平均，超过Doubao 2.0 Lite（70.5）和DeepSeek-V4-Flash（71.4），低于Kimi K3（77.1）。实时交互模式下宏平均为70.4，与Doubao 2.0 Lite持平，表明边说边想机制在推理与实时性之间的权衡是可接受的。

Agent任务评估使用$\tau$-Voice基准。StepAudio 3 Realtime的宏平均任务成功率为56.0%，其中电信领域得分70.2%，为所有模型最高，超过第二名Grok 6.5个百分点；航空得分60.0%，接近最佳62.0%；零售得分37.7%，与Grok的49.7%有较大差距，是明确的能力短板。

## 四、展望

StepAudio 3 Realtime展示了实时语音交互中同时保持推理深度与对话流畅度的可行性。Adaptive Thinking对推理频率的分配尚未完全对齐任务的实际收益——推理类别的think rate为59.5%，尽管推理对收益最大，而忠实度类别反而达79.2%。零售工具调用、多轮约束保持和推理资源分配是三个明确的改进方向。随着语音Agent在客服、教育、车载等场景落地，如何让模型在长时间对话中持续保持对约束的记忆和推理的精准分配，将是下一代实时语音模型需要回答的核心问题。
