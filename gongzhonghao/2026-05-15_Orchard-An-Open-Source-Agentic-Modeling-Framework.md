# 微软开源Orchard框架：Agent训练成本直降90%，SWE-bench性能超越10倍大模型！

## 引言

训练一个能够自主规划、推理、使用工具并与外部环境交互的Agent，是当前大模型研究的核心难题。开发者们面临的不仅是模型能力本身的挑战，更有一个“隐形杀手”——**环境层**。无论是软件工程中克隆仓库、安装依赖、运行测试，还是网页导航中的多轮交互，每次训练都需要在隔离的沙箱中反复执行上百次操作。当训练规模扩展到数千并发任务时，环境管理的复杂度、成本和延迟，成为了制约Agent技术进步的首要瓶颈。

现有方案，要么依赖E2B这样的托管服务，成本高昂且可控性差；要么像MegaFlow这样将环境层与训练框架深度耦合，导致数据和流程难以复用。

微软研究院与哥伦比亚大学、UIUC团队联合提出的 **Orchard框架**，给出了一个截然不同的答案：将环境层解耦为一个**薄层、开源、可复用**的独立服务。基于这一架构，他们在三个Agent领域取得了突破性成果——SWE-bench Verified上67.5%的修复率，Web导航任务68.4%的平均成功率，同时**将训练成本降低至云服务商托管方案的1/10**。

## 一、核心方法：薄层环境服务Orchard Env

### 1.1 架构设计：三层的极致解耦

Orchard框架的核心是 **Orchard Env**，一个Kubernetes原生的环境服务。其架构采用三层分离设计，如下图所示。

![图1：Orchard Env三层架构](https://arxiv.org/html/2605.15040v1/figures/orchard-architecture.png)

该架构的核心创新在于：
- **控制面与数据面分离**：Pod创建/删除等生命周期管理（冷路径）通过Kubernetes API Server进行；而命令执行、文件I/O等实时交互（热路径）则直接路由到沙箱Pod的IP，**完全绕过了kubectl exec/WebSocket的开销**。
- **运行时Agent注入**：一个轻量级的FastAPI服务，通过init容器在Pod启动时动态注入到用户提供的任意Docker镜像中，无需对镜像做任何修改，支持数百种异构任务环境。
- **可组合性**：该服务不耦合于任何Agent框架、推理后端或训练器，同一个环境服务可以同时服务于轨迹蒸馏、在线强化学习（RL）rollout和评估。

### 1.2 性能验证：0.28秒延迟与100%可靠性

论文对Orchard Env进行了严格的系统评估，结果如下表所示：

| 系统 | 平均命令执行延迟（秒） |
| ------ | -------------------------- |
| **Orchard Env** | **0.280** |
| SkyPilot Code Sandbox | 0.284 |
| E2B | 0.747 |
| Modal | 2.046 |

在1,000个并行沙箱的压力测试中，Orchard Env实现了**100%的成功率**（创建→4次执行→删除），端到端仅耗时26秒，能够轻松应对典型Agent训练所需的并发吞吐量。

### 1.3 成本优势：10倍于托管服务

更令人关注的是成本对比。对于128个并行的2-vCPU、8GiB沙箱运行240小时的场景：

| 系统 | 每沙箱小时成本 | 总成本（美元） |
| ------ | ---------------- | ---------------- |
| Daytona | $0.230 | $7,078 |
| E2B | $0.230 | $7,078 |
| Modal | $0.335 | $10,305 |
| **Orchard Env（按需）** | **$0.109** | **$3,362** |
| **Orchard Env（竞价实例）** | **$0.022** | **$673** |

Orchard Env利用Kubernetes的竞价实例和自动扩缩容，在按需模式下成本降低53%，竞价模式下**成本仅为托管的1/10**。

## 二、三大训练配方：从SWE到GUI再到个人助理

在Orchard Env之上，论文构建了三个Agent训练配方，展示了同一环境抽象如何支持不同领域。

### 2.1 Orchard-SWE：软件工程Agent的进阶之道

解决软件工程任务面临两大瓶颈：**监督信号稀疏**和**奖励信号稀疏**。Orchard-SWE提出了三项关键技术。

**（1）大规模多教师轨迹蒸馏**：从MiniMax-M2.5和Qwen3.5-397B两个教师模型，在三个任务源上蒸馏了 **107K条轨迹**。与大多数只保留成功轨迹的方法不同，Orchard-SWE**同时保留了未解决的失败轨迹**。

**（2）信用分配监督微调**：对于失败轨迹，研究者引入了一种基于**时序差分（TD）价值估计**的信用分配方法：

$$V(s_t) = \mathbb{P}(\text{resolve} \mid h_t, \text{outcome})$$

使用教师模型对轨迹中每一步的成功概率进行回顾性估计，然后提取出**上升片段**：

$$c_t = V(s_{t+1}) - V(s_t)$$

将这些先前被丢弃的“局部进展”转化为有效监督信号。

**（3）平衡自适应Rollout（BAR）**：针对强化学习中奖励方差为零、产生无效梯度的痛点，BAR算法为每个提示动态生成轨迹直到构建出正负奖励平衡的训练组：

$$A_{i,t} = \frac{r_i - \text{mean}(\{r_1, r_2, \ldots, r_N\})}{\text{std}(\{r_1, r_2, \ldots, r_N\})}$$

### 2.2 实验结果：67.5%的SWE-bench与跨越框架的泛化能力

![图2：Orchard-SWE性能对比](https://arxiv.org/html/2605.15040v1/x1.png)

表7展示了Orchard-SWE在SWE-bench Verified上的核心结果：

| 模型 | 框架 | 修复率（%） |
| ----------------------- | ------------- | ------------ |
| Qwen3-30B-A3B-Instruct | OpenHands | 22.0 |
| Qwen3-Coder-30B-A3B | OpenHands | 51.6 |
| Scale-SWE-Agent | OpenHands | 64.0 |
| **Orchard-SWE（SFT）** | **mini-swe-agent** | **64.3** |
| **Orchard-SWE（SFT+RL）** | **mini-swe-agent** | **67.5** |

更值得关注的是跨框架的**泛化能力**。在单框架训练时，模型几乎完全“锁死”在训练框架中——Scale-SWE在其他框架上完全无法生成有效输出，OpenSWE-32B从62.4%骤降至3.6%。而Orchard-SWE的多框架训练，使其在三个不同框架间（Kimi-CLI为未见框架）仍能维持45%-64%的性能，展现了真正的软件工程技能而非框架绑定。

### 2.3 Orchard-GUI与Orchard-Claw：极少量数据下的惊人成果

**Orchard-GUI**：仅用 **0.4K蒸馏轨迹**和 **2.2K训练任务**，在4B视觉语言模型上训练浏览器Agent。结果如下：

| 模型 | WebVoyager | Online-Mind2Web | DeepShop | 平均 |
| --------- | ------------ | --------------- | ---------- | ------ |
| Orchard-GUI（SFT+RL） | 74.1% | 67.0% | 64.0% | **68.4%** |

该结果不仅大幅超越所有开源模型，还**接近甚至持平GPT-5和Gemini等闭源系统**，并且超越了其235B的教师模型，证明了环境接地RL的潜力。

**Orchard-Claw**：针对个人生产力助手，仅用 **0.2K合成任务**训练，在Claw-Eval上达到59.6% pass@3，搭配更强的ZeroClaw框架时提升至73.9%。

## 三、核心结论：环境层是复用性的基石

这项研究的核心结论清晰而有力：**环境层不是构造基础设施，而是决定Agent建模制品可复用性的核心基础**。一个薄层、开源、框架无关的环境服务，使得轨迹数据、SFT配方、RL Rollout和评估协议能够在不同领域、Agent框架和流水线阶段之间自由转移。

Orchard证明了，可扩展的Agent建模不必依赖于封闭的专有系统。通过基础设施层面的精心解耦，研究者可以同时获得**高性能、低成本和高可复现性**。

对于正在开发复杂Agent应用的团队来说，一个值得思考的问题是：**你的训练流程中，环境层是否已经成为了瓶颈？是否应该重新审视基础设施设计，将其从“被动的执行者”转变为“主动的创新推动者”？**
