# UC San Diego等机构发布JetSpec：并行树草稿破解推测解码天花板，解码速度最高提升9.64倍

## 一、引言

大语言模型（LLM）的推理时延一直是部署应用的「阿喀琉斯之踵」。当模型在处理数学推理、代码生成等复杂任务时，自回归的逐 token 生成模式导致响应速度成为瓶颈。传统解决办法中的推测解码（Speculative Decoding, SD）虽能通过草稿模型并行验证提升速度，但其面临一个根本性的扩展瓶颈：当增加草稿预算时，只有在接受率保持高位且草稿开销很低时，加速效果才会提升。如今，来自 UC San Diego、浙江大学、UIUC 等机构的研究者联合提出 **JetSpec**，通过一种创新的因果并行树草稿框架，在 H100 GPU 上实现最高 **9.64 倍** 的端到端加速，一举突破这一天花板。

## 二、核心方法

### 2.1 破解因果-效率困境

传统头式推测解码方法陷入难以调和的 **因果-效率困境**。一方面，自回归草稿器（如 EAGLE）能生成高质量路径条件候选，但草稿开销随树深度线性增长。另一方面，双向块扩散草稿器（如 DFlash）单次前向传播可生成全部位置，但所生成的分支无关边际分布会导致看似合理却互不一致的候选树，浪费预算并降低接受率。

JetSpec 的核心洞察在于：**要实现并行树草稿，每个节点的分布必须基于其自身所在分支的前缀进行条件化**。为此，论文提出训练一种因果并行草稿头，在保持并行前向传播高效性的同时，保留分支间的因果依赖关系。

### 2.2 树因果注意力掩码

具体而言，JetSpec 采用头式草稿架构，从冻结的目标模型中提取融合的隐藏状态特征。与普通并行草稿不同，该方法引入 **树因果注意力掩码**，使得每个树节点只能关注原始前缀及其祖先节点，而不能关注后代或无关的兄弟分支：

$$M_{v,u}=\begin{cases}0,&\text{if }u\in\mathrm{Anc}(v)\cup\{v\},\\-\infty,&\text{otherwise},\end{cases}$$

这一掩码机制使得所有树节点可以并行处理，同时保证每个分支遵循类似自回归的依赖结构。由此产生的分支级因子分解完美对齐目标模型的自回归因子分解：

$$q(\pi(v)\mid x)=\prod_{u\in\pi(v)}q(y_{u}\mid x,h_{x}^{o},\pi_{<u})$$

### 2.3 训练与蒸馏目标

JetSpec 的草稿头通过软标签蒸馏目标进行训练。论文实验表明，前向 KL（Forward KL）散度比反向 KL（Reverse KL）更适用于此类树草稿任务。前向 KL 鼓励草稿分布覆盖目标模型的概率质量，保留软标签信息，而模式寻找型的反向 KL 会将概率过度集中在高置信模式上，导致性能下降 36-46%。

### 2.4 并行树构建与验证

在推理阶段，因果草稿头只需一次前向传播即可获得所有草稿深度的 logits。树扩展过程基于累积草稿对数概率进行分支评分，反复弹出最高分可扩展节点扩展，直至预算耗尽。目标模型随后使用树注意力并行验证所有候选路径，通过标准的推测采样规则决定接受哪些 token。

![图2：典型SD与超低开销SD的速度扩展对比](https://arxiv.org/html/2606.18394v3/x2.png)  ![图2b：不同草稿开销下的加速情况](https://arxiv.org/html/2606.18394v3/x3.png)

$$Speedup=\frac{1-\alpha^{N+1}}{(1-\alpha)(Nc+1)}$$

该公式揭示了一个关键规律：降低每 token 草稿成本 $c$ 并提升接受率 $\alpha$，对于实现长草稿的加速扩展至关重要。JetSpec 正是同时优化这两个因子。

## 三、实验

### 3.1 全面超越主流基线

论文在 Qwen3-8B 和 Qwen3-30B-A3B 模型上全面评估了 JetSpec，与 EAGLE-3、DFlash 及树变体 DDTree 进行对比。

| 方法 | 预算 | MATH-500加速比 | 平均接受长度 $\tau$ |
|------|------|----------------|-------------------|
| EAGLE-3 | 64 | 2.36× | 4.13 |
| DDTree | 64 | 6.51× | 7.16 |
| **JetSpec** | 64 | **6.76×** | **7.42** |
| DDTree | 128 | 8.27× | 9.19 |
| **JetSpec** | 128 | **8.93×** | **9.95** |
| DDTree | 256 | 8.78× | 9.81 |
| **JetSpec** | 256 | **9.64×** | **10.76** |

在低预算（16 token）下，JetSpec 与 DFlash 表现相当。但随着预算增至 32 以上，DFlash 出现饱和甚至下降，而 JetSpec 仍能将额外预算有效转化为更长接受前缀，充分验证其因果树草稿的设计优势。

### 3.2 系统级性能

在集成 vLLM 的端到端服务评测中，JetSpec 展现出负载感知的适配能力。批次大小为 1 时，预算从 16 提升至 128，吞吐量从 443.3 飙升至 968.2 TPS，加速比从 3.09 倍增至 6.75 倍。随批次增大，过大的预算收益递减，这表明实际部署中应根据负载动态选择预算策略。

### 3.3 关键消融分析

论文彻底剖析了因果头与扩散头的对比。在 MATH-500 基准上，因果头在所有 $\gamma$ 设置下保持 $\sim$8.3-8.5 倍加速，而扩散头在极端参数下（$\gamma=0$ 或 $\gamma=15$）性能急剧下降至 5.46-6.17 倍。一个失败案例生动说明了原因：扩散头将概率仅为 -63.32 nats 的互斥分支排在首位，而因果头正确识别了概率 ≈-0.08 nats 的连贯分支，使树验证接受 6 个 token 而非 3 个。

## 四、展望

JetSpec 的提出为大模型推理加速开辟了新方向。其因果并行树草稿的设计范式不仅适用于当前的 Qwen3 系列，对 MoE 架构同样有效。研究者指出，该方法可以进一步融入预训练或中期训练阶段，未来结合动态预算调度策略，有望在更复杂的 Agent 场景和实时交互应用中释放更大潜力。对于开发者和部署工程师而言，JetSpec 提供了一个强有力的新工具，可以显著降低用户感知延迟，提升大模型应用的体验。
