# 人大复旦联手打造Agent工具空间：35B模型平均提升18分！

## 一、引言

让 Agent 查询资料、更新表格再发送通知，听起来只是几步操作，实际却涉及多个系统之间的数据传递、状态修改和异常处理。工具越多、任务链越长，任何一步的参数或状态出错，都可能让后续操作失效。

训练数据是关键瓶颈。常见做法是先合成业务场景和数据库，再围绕它们生成工具与任务。但这样得到的工具接口可能偏离真实服务，工具之间的连接也未必经过执行验证；跨环境任务更难自然构造。

来自中国人民大学、复旦大学等机构的研究者提出 **ToolSpace**：先从工具调用轨迹中恢复真实出现过的连接关系，再沿这些关系生成可执行、可验证的长链任务。它不仅用于训练 Agent，也能为现有基准扩展更复杂的跨环境测试。

## 二、核心方法

![图1：ToolSpace从调用轨迹构建工具空间，并生成可验证任务](https://arxiv.org/html/2611.05036v1/ToolSpace_1025.png)

### Tool Space Exploration：从调用轨迹恢复工具关系

ToolSpace 首先收集工具交互轨迹，包括在真实 MCP 服务上执行的调用、开放 Agent 数据集，以及经过接口匹配过滤的合成工具轨迹。**MCP** 可以理解为连接模型与外部工具、数据服务的协议。

系统不是简单地把每个工具当成一个节点：同一工具使用不同的**归一化参数配置**，也可能形成不同节点，因为它们的输出和后续依赖可能不同。

接着，系统只考察轨迹中**相邻的两次调用**，用确定性规则提取三类边，而不是让大模型主观判断工具能否组合：

- **数据依赖**：后一个调用使用前一个调用输出的值，且字段类型匹配。
- **状态依赖**：前一个调用修改某个对象，后一个调用读取或继续修改同一对象。
- **重试依赖**：前一次调用报错，轨迹切换工具后成功，记录可恢复错误及后续操作。

例如，查询客户信息后把客户 ID 传给更新接口，属于数据依赖；修改记录后再读取同一记录，则涉及状态依赖。

边的权重由轨迹中的转移频率确定：

$$w(v_i,v_j)=\frac{N_{ij}}{N_i}$$

其中，$N_i$ 是节点 $v_i$ 的出现次数，$N_{ij}$ 是 $v_j$ 紧随 $v_i$ 出现的次数；权重越高，表示该转移在已有轨迹中越常见。

低频边和来源无法追溯的数据边会被过滤，以减少把 `limit=10` 之类常见常量误判为依赖。随后，工具按连接密度聚成环境，并结合真实 MCP 服务配置组织。

环境数据也按需准备：包含新增、修改或删除操作的环境，需要合成数据库并检查状态转移；状态查询工具使用记录的输出初始化快照；无状态工具则在匹配调用时复用缓存结果。这避免了为每个工具都从头构造完整数据库。

### State-Aware Random Walks：执行并回滚工具链

有了图，还不能直接把任意路径当成任务：两条边分别在历史中出现过，不代表拼接后一定能在当前状态下执行。

ToolSpace 因此进行**状态感知随机游走**。从初始快照出发，系统先筛选满足依赖、状态前提和参数来源要求的后继节点，再按边权采样：

$$P(v_{t+1}=v\mid v_t)=\frac{w(v_t,v)}{\sum_u w(v_t,u)}$$

分母只包含当前状态下可选的后继节点，因此历史中更常见、且此刻可执行的连接更容易被选中。

每选一步，系统就实际执行工具并更新状态。如果执行失败或结果违反所经过的依赖关系，系统会回滚到上一步快照并重新采样；多次回滚仍无法继续的链会被丢弃。轨迹中预期的可恢复错误则可作为重试关系的一部分保留。

游走可以指定目标链长度和跨越的环境数量。生成后的链还要从初始状态重放，检查整条路径的状态连续性和可执行性。

### Reverse Verifiable Task Synthesis：从工具链生成任务与训练数据

通过重放的工具链，接下来被“反编译”为自然语言任务：语言模型根据调用链和状态变化描述用户目标，但不直接写出工具名称或调用顺序。

系统同时生成三类**断言式验证**：检查最终状态、检查关键中间状态，以及检查输出中必须出现的字段。只有从初始状态重放后通过全部检查的样本才会保留，并附带任务、验证脚本、工具链和初始快照。去重后，教师模型还会为保留任务生成轨迹，并再次通过验证筛选。

训练阶段先使用合成轨迹进行**监督微调**（SFT）。部分样本进一步用于 Agent 强化学习：通过 GRPO 进行多次策略采样，以执行验证是否通过作为二元奖励，再利用同组轨迹的相对奖励更新模型。这样，训练信号关注的是任务执行结果，而不只是工具调用格式。

## 三、实验

ToolSpace 收集了超过 **20 万条**原始 Agent—工具交互轨迹，并在任务和轨迹层面排除与测试集重合的样本。最终构建的图包含 **2,042 种规范工具、77,760 个调用模式节点**和 **804 个环境**；数据、状态、重试边分别占 69%、25% 和 6%。

合成数据共包含 **34,376 条 SFT 样本**。在至少调用工具五次的轨迹中，平均每条调用 **18.86 次**、跨越 **2.29 个环境**。强化学习还使用了 653 个经过额外难度筛选的样本。

在七项长链工具使用基准上，Qwen3.6-35B-A3B 的平均得分从 **23.0** 提升到 **41.0**，加入 Agent 强化学习后达到 **43.2**。其中，AutomationBench 从 8.2 升至 45.8；强化学习后的 Banking 得分从 SFT 阶段的 34.0 升至 42.3。

更大模型上，GLM-5.2 的七项平均分从 **44.6** 提升至 **56.6**，与表中 Claude Opus 5 的平均分持平；这并不意味着两者在每项任务上表现相同。论文综合使用官方榜单、提供方结果和本地复现结果，ToolSpace 结果取三次独立运行的平均值。

ToolSpace 还将 AutomationBench 和 $\tau^3$-Bench Banking 扩展为 Pro 版本，分别包含 **300** 和 **98** 个任务。七个前沿模型在两套 Pro 测试上的得分均低于标准版本；其中 DeepSeek-V4.1-Flash-1017 在 AutomationBench 上从 **60.5** 降至 **22.3**，下降 **38.2 个百分点**。标准版与 Pro 版任务不同，这一差距反映的是升级测试下的表现变化，而非单独归因于某一种难度因素。

![图2：训练数据规模与环境规模的扩展结果](https://arxiv.org/html/2611.05036v1/fig_scaling.svg)

消融实验进一步说明各组件的作用：在 35B 设置下，移除状态边使 Banking 得分从 **34.0** 降至 **21.5**；用大模型判断的边替代执行轨迹挖掘的边，使 AutomationBench 从 **45.8** 降至 **37.8**。数据和环境规模扩大时，整体表现也随之改善，但中间规模存在波动。

成本实验以合成文件数量作为代理指标：在抽样的 500 个环境中，按需构造使文件数从 **2,724** 降至 **1,218**，减少 **55.3%**。这一结果尚未直接衡量 Token、运行时间或计算成本；缓存回放也只覆盖匹配的调用，不能等同于对任意实时工具输入的完整模拟。
