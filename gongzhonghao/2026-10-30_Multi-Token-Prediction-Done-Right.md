# MIT改进大模型MTP：1.2B模型解码快1.1%，只改一行！

## 一、引言

大模型生成文字时，通常每次只预测下一个 token。为了同时提升训练效果和推理速度，越来越多模型引入**多 token 预测（MTP）**：在预测下一个 token 的同时，也训练额外模块预测更远位置的 token。

这些额外模块还能充当推测解码的“起草者”：先快速提出候选，再由主模型验证。问题在于，标准 MTP 用真实数据训练起草者，而推测解码更关心的，是起草者能否与主模型的预测分布对齐。两者相关，却并不完全相同。

MIT 研究者在论文 *Multi-Token Prediction Done Right* 中指出，标准 MTP 的梯度已经包含对齐主模型的信号，但它被另一部分噪声较大的梯度掩盖。研究者提出 **Soft-MTP**，通过调整梯度流向提取有用信号。在最大 1.2B 参数的实验中，该方法相较标准 MTP 改善了困惑度、推测解码和部分下游任务表现，同时保留原有训练计算路径。

## 二、核心方法

### MTP 梯度分解：找出已有的自蒸馏信号

标准 MTP 在共享主干之外增加预测头。每个预测头产生隐藏状态，再通过与下一 token 预测（NTP）共享的线性输出层，得到未来某个位置的 token 分布。训练时，NTP 和 MTP 都使用真实 token 作为交叉熵目标。

关键是**位置对齐**。假设 MTP 在位置 $t$ 预测位置 $t+k+1$ 的 token，那么可以找到位置 $t+k$ 的 NTP 输出：两者预测的是同一个 token，只是 NTP 基于更靠后的前缀作出预测。

![图1：MTP预测与位置对齐的NTP分布](https://arxiv.org/html/2610.38331v1/images/pos_aligned_ntp.png)

记 MTP 分布为 $p$，对齐后的 NTP 分布为 $q$，真实 token 的独热向量为 $x$，共享输出层为 $W$。标准 MTP 对隐藏状态的梯度可以精确拆成：

$$
g_{\text{hard}}
=\underbrace{W^{\intercal}(p-q)}_{g_{\mathrm{KL}}}
+\underbrace{W^{\intercal}(q-x)}_{g_{\text{res}}}
$$

这个分解表明，标准 MTP 梯度同时包含让 MTP 靠近 NTP 分布的 **KL 自蒸馏梯度**，以及由对齐 NTP 分布与真实 token 之差产生的**残差梯度**。

两部分的作用不同：前者直接服务于起草者与验证者的分布对齐；后者既包含 NTP 预测误差，也包含真实 token 采样带来的噪声。移除残差会让训练目标偏向模型自己的 NTP 分布，而不再完全等同于拟合真实数据；但对推测解码而言，匹配验证者恰恰是有价值的方向。

### KL 梯度恢复：复用交叉熵，改变反向传播

直接计算自蒸馏 KL 散度，需要同时取得教师和学生在整个词表上的分布。词表较大时，这会增加显存开销，也难以直接利用常见的融合交叉熵算子。

**KL 梯度恢复技巧**换了一条路径：保留原有的 NTP 和 MTP 交叉熵计算，只在隐藏状态之间增加一条反向传播路径。其构造如下：

$$
\tilde{\mathbf h}_{t}
=\mathbf h_{t}^{(0)}
+\sum_{\substack{k=1\\t-k\geq 1}}^{K}
\left[\operatorname{sg}\!\left(\mathbf h_{t-k}^{(k)}\right)
-\mathbf h_{t-k}^{(k)}\right]
$$

其中 $\operatorname{sg}$ 表示停止梯度：方括号在前向计算中数值为零，却会在反向传播时向对应的 MTP 隐藏状态传入负梯度。

这条负梯度恰好抵消 MTP 梯度中的残差，因此：

$$
\nabla_{\mathbf h_t^{(k)}}
\left(\tilde{\mathcal L}_{\text{NTP}}+\mathcal L_{\text{MTP}}^{(k)}\right)
=g_{\text{hard}}-g_{\text{res}}=g_{\mathrm{KL}}
$$

这意味着，MTP 隐藏状态及其上游模块收到的是精确恢复的 KL 自蒸馏梯度，而不需要显式构造 KL 所需的完整词表分布。

示意代码中的关键改动只有一行：

```python
h0[:, k:] += hk.detach() - hk
```

前向时，`detach()` 前后的数值相同；反向时，只有未被 `detach()` 的部分传递负梯度。实际实现还需处理 MTP 损失权重、不同预测头的目标数量和位置掩码，不能将示意代码直接视为完整训练实现。

![图2：Soft-MTP的梯度路由示意](https://arxiv.org/html/2610.38331v1/images/soft_mtp_explanation_8.png)

### Soft-MTP：对不同模块采用不同梯度

Soft-MTP 并非把所有训练梯度都替换成 KL：

- **MTP 预测头和共享主干**：MTP 路径上传播恢复出的 KL 梯度，使预测更贴近对齐的 NTP 分布。
- **共享输出层**：保留 MTP 交叉熵梯度，继续用真实数据训练输出映射。
- **原有 NTP 路径**：前向数值和 NTP 自身的梯度保持不变。

这种分工也是 Soft-MTP 与直接最小化 KL 的重要区别。后者也会用 KL 梯度更新共享输出层；而共享输出层同时承担 NTP 和 MTP 的读出，训练它靠近数据，可能有助于避免仅通过改变读出方式来缩小两种预测的差异。

## 三、实验

研究者使用 LLaMA 风格模型，在 FineWeb-Edu 上训练约 315 亿 token，主实验的基础模型规模从 167M 到 1.2B 参数。MTP 采用 DeepSeek 风格的顺序预测结构，设置三个额外预测头；对比包括纯 NTP、标准 MTP、直接计算 KL 的 KL-MTP 和 Soft-MTP。

**梯度分析支持了分解动机。**实验以梯度期望方向的强度相对于批次间方差来衡量信噪比：从 167M 到 1.2B，KL 分量的信噪比分别约为残差的 4.1 倍到 4.6 倍；但残差约占传入共享主干的 MTP 梯度份额的 80%。在冻结输出层的代理分析中，沿残差对应的更新方向移动会增加 NTP 损失；这一分析用于描述梯度倾向，不等同于优化器的实际完整更新。

![图3：不同模型规模下的梯度信噪比](https://arxiv.org/html/2610.38331v1/images/snr_across_scale_muon.png)

在主实验的各个规模下，Soft-MTP 的 NTP 困惑度均低于标准 MTP；从 689M 参数起，MTP 困惑度也更低。**困惑度**越低，表示模型对测试文本的概率预测通常越好。另一次 332M 参数、约 73 亿 token 的较短训练中，研究者调整了 MTP 权重和预测跨度，Soft-MTP 在所测试设置下均取得更低的 NTP 与 MTP 损失。

**推测解码的收益明确但幅度适中。**在 1.2B 模型的 FineWeb-Edu 测试中，相对于各自的普通自回归解码，标准 MTP 的速度比为 1.74 倍，Soft-MTP 为 1.76 倍，后者相对前者约快 1.1%。在五个测试领域平均，Soft-MTP 在各模型规模上的接受长度提升约 1.8%—2.2%，速度提升约 1.4%—1.5%。

**训练成本接近标准 MTP，但不等于没有 MTP 成本。**单张 NVIDIA H200 上、1.2B 模型与三个预测头的测试中，标准 MTP 和 Soft-MTP 使用融合交叉熵时的峰值显存均为 107.0 GB，吞吐量分别为 49,783 和 49,748 token/秒；直接计算 KL 的 KL-MTP 为 46,990 token/秒、128.1 GB。Soft-MTP 相比纯 NTP 仍需承担额外 MTP 模块的成本。

下游测试中，1.2B Soft-MTP 的平均零样本准确率为 57.31%，标准 MTP 为 56.80%；并非每个单项任务都提升。移除 MTP 头并仅用 NTP 损失微调后，Soft-MTP 在 HumanEval 的 **pass@64**（64 次采样中至少一次通过的指标）上达到 43.90%，标准 MTP 为 40.85%；GSM8K 准确率分别为 49.66% 和 48.60%。不过，直接 KL-MTP 在数学微调上更强：其 GSM8K 和 MATH-500 准确率分别为 50.34% 和 26.00%，高于 Soft-MTP 的 49.66% 和 25.00%。
