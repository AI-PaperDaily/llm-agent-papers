# 清华&达摩院推出Dockerless：环境无关代码验证器，SFT+RL全流程超越Docker方案，AUC提升14.3%

## 引言

程序验证器是训练编码Agent的核心组件。无论是为监督微调（SFT）筛选高质量轨迹，还是为强化学习（RL）提供奖励信号，验证器的准确性直接决定了Agent能否真正学会修复代码Bug。

当前主流的验证方案依赖于在隔离的Docker容器中执行测试用例，这要求为每个代码仓库定制构建Docker镜像、解析依赖、识别相关测试、编写执行脚本。这种工程开销极其高昂——许多私有代码库、企业遗留系统甚至无法复现编译环境。研究显示，即使最先进的自动化流水线，也只能在有限比例的候选仓库上成功搭建环境。

针对这一瓶颈，清华大学与阿里达摩院的研究团队提出**Dockerless**——一种完全无需执行环境（Environment-Free）的智能体验证器。该方法不依赖任何Docker容器，通过让Agent主动探索代码仓库收集证据来评判补丁正确性，在验证器评估基准上超越最强开源方案14.3个AUC点。更关键的是，Dockerless使完整的后训练流水线（SFT过滤+RL奖励）彻底摆脱环境依赖，最终模型在SWE-bench Verified/Multilingual/Pro上分别达到62.0%、50.0%和35.2%的解决率，超越Qwen3.5-9B基线2.4/8.7/2.9个点，性能与依赖Docker环境的后训练方案持平。

## 一、核心方法：Agent驱动的证据收集式验证

### 1.1 问题设定与验证器设计理念

传统的环境无关验证器（如LLM直接打分）仅利用表面信息（如文本差异）进行判断，这对于复杂的软件工程任务远远不够——例如，修改的函数是否被故障行为实际调用？替代实现是否正确集成到周围模块？这些问题需要深入仓库上下文的证据才能回答。

Dockerless的核心设计理念是：**将验证本身转化为一个Agent问题**。给定一个Issue描述、一个参考补丁和一个候选补丁，Dockerless不直接比对文本，而是先生成一组验证问题，然后派遣子Agent深入代码库收集证据，最终根据证据做出判决。

![图1：不同验证器对比。Docker测试准确但依赖昂贵环境，LLM打分器绕过环境但仅基于表面信息，Dockerless深度探索仓库进行判断。](https://arxiv.org/html/2606.28436v1/x1.png)

### 1.2 两阶段架构：问题驱动+证据聚合

Dockerless的架构分为两个阶段：

**阶段一：问题生成与证据探索**

给定Issue和参考补丁，模型首先提出$K$个验证问题（$K=2-4$）。这些问题涵盖：修复应该在仓库的哪个位置生效？补丁代码的预期行为是什么？哪些测试或断言可以确认正确性？其他部分是否会因此断裂？

针对每个问题，一个子Agent使用只读Shell工具（如find、grep、rg）探索仓库，返回带有证据支撑的简短答案$A_k$。$K$个子Agent并行运行以确保效率。

**阶段二：综合判决**

收集所有证据后，Dockerless对候选补丁做出二值判决（1表示正确补丁）。模型输出一个二元token（0/1），其logits转换为连续评分：

$$r_{\phi}(x,y)=\frac{\exp(\ell_{1})}{\exp(\ell_{0})+\exp(\ell_{1})}$$

其中$\ell_0$和$\ell_1$分别代表0和1的logits。

![图2：Dockerless架构。输入Issue $x$、参考补丁$y_{ref}$和候选补丁$y$，先生成$K$个验证问题并派遣并行子Agent收集证据，再综合判决输出评分。](https://arxiv.org/html/2606.28436v1/x2.png)

### 1.3 训练策略：拒绝采样保证信号一致性

Dockerless的训练采用拒绝采样框架。每个训练样本是一个四元组$(x, y_{ref}, y, r^{\star})$，其中$r^{\star}\in\{0,1\}$是通过执行原子测试获得的真实标注（ground-truth）。

训练过程如下：教师模型驱动的Agent为每个样本生成完整的问答-判决轨迹$\tau$，产生判决$\hat{r}$。仅保留$\hat{r}$与$r^{\star}$一致的轨迹构成数据集$\mathcal{D}_{rej}$。这意味着模型学习的是**如何通过正确推理得出正确结论**，而不是靠运气匹配答案。

训练目标为标准的下一个token交叉熵：

$$\mathcal{L}_{\phi}=-\mathbb{E}_{\mathcal{D}_{\text{rej}}}\left[\sum_{t=1}^{T}\log p_{\phi}(z_{t}\mid x,y_{\text{ref}},y,z_{<t})\right]$$

其中$z = (z_1, \ldots, z_T)$是问答-判决轨迹的token序列。一个统一的模型骨干同时承担问题生成、子Agent探索和最终判决三个角色。

![图3：Dockerless训练流水线。教师生成的问答-判决轨迹通过拒绝采样（匹配预测判决与真实标注）后用于微调基础模型。](https://arxiv.org/html/2606.28436v1/x3.png)

## 二、实验：全面超越基线，匹配Docker方案

### 2.1 验证器性能评估

研究者在SWE-bench Verified和Multi-SWE-bench Flash上构建了776个样本的平衡验证器评估基准。Dockerless与两类基线对比：四个前沿LLM（零样本裁判）和四个开源训练验证器。

| 模型 | SWE-bench Verified AUC | Multi-SWE Flash AUC |
|------|------------------------|---------------------|
| DeepSeek-V3.2 | 69.4 | 58.5 |
| Kimi-K2.5 | 70.7 | 63.9 |
| GLM-5 | 73.2 | 62.5 |
| GPT-5.4 | 75.9 | 59.5 |
| SWE-Gym Verifier | 61.0 | 53.7 |
| R2E-Gym Verifier | 64.3 | 55.1 |
| DeepSWE Verifier | 66.7 | 62.9 |
| **Dockerless** | **81.0** | **72.1** |

Dockerless以81.0和72.1的AUC分远超所有基线：相比最强开源验证器DeepSWE Verifier提升14.3个点（Verified）和9.2个点（Multi-SWE），相比最强LLM裁判GPT-5.4提升5.1个点和8.2个点。

### 2.2 全无环境后训练效果

研究者使用Qwen3.5-9B作为骨干模型，构建了完整的无环境后训练流水线：

| 模型 | 训练方式 | 环境依赖 | Verified | Multilingual | Pro |
|------|---------|---------|----------|-------------|-----|
| Qwen3.5-9B | - | - | 59.6 | 41.3 | 32.3 |
| Env-SFT-9B | SFT | 是 | 60.0 | 48.3 | 33.9 |
| Dockerless-SFT-9B | SFT | **否** | 60.6 | 47.7 | 35.3 |
| Dockerless-RL-9B | SFT+RL | **否** | **62.0** | **50.0** | **35.2** |

关键发现：
- **无环境SFT匹配有环境SFT**：Dockerless-SFT-9B在三个基准上与Env-SFT-9B性能接近（60.6 vs 60.0，47.7 vs 48.3，35.3 vs 33.9）
- **无环境RL接近有环境RL**：Dockerless-RL-9B与Test-Execution RL（使用Docker执行测试的oracle奖励）几乎持平（62.0 vs 62.4，50.0 vs 51.3，35.2 vs 35.7）
- **超越所有开源同规模模型**：比SWE-Lego-8B提升20.8/31.0/19.1个点

### 2.3 SFT数据过滤效果

研究表明，原始无环境轨迹直接训练甚至可能降低性能（All 16K达到58.8%，低于基线的59.6%）。Dockerless筛选出的4K轨迹在三个基准上大幅优于随机采样4K（60.6 vs 58.2，47.7 vs 44.3，35.3 vs 32.0），且与有环境收集的4K轨迹性能相当。

![图5：验证问题数量$K$对AUC的影响。从$K=0$的78.3提高到$K=4$的80.8，之后趋于平稳。](https://arxiv.org/html/2606.28436v1/x5.png)

### 2.4 案例研究：表面形式不同但功能等价

一个典型案例展示了Dockerless的核心优势。在matplotlib的offsetText颜色问题上，候选补丁使用内联条件语句而非参考补丁的辅助变量重构。两种LLM裁判（文本相似度0.468，DeepSWE Verifier 0.035）均给出低分，但Dockerless派生子Agent验证了修复应用到了XAxis和YAxis的初始化路径，且语义一致，给出0.996的高分，与执行测试结果完全一致。

## 展望

Dockerless的提出标志着代码验证迈入了一个新范式：**证据驱动的智能体验证**。它证明了在RL训练中，Agent执行成本占据绝大多数时间（约92.8%），验证器额外开销微乎其微，但验证质量的提升却可带来显著的性能增益。

这一技术对于私域代码库、缺乏测试套件的企业遗留系统、以及需要超大规模后训练的场景尤为关键。研究者认为，Agent式的证据收集验证为代码奖励建模提供了全新视角，开启了在无法复现执行环境的真实仓库上进行后训练的规模化路径。

Dockerless的成功也提出了一个有趣的问题：在不需要Docker环境的前提下，纯代码分析与推理能否达到甚至超越执行测试的效果？这或许将推动模型在代码理解深度上的进一步进化。
